# CDL-云签速印 路线图

依据：对一款同类标签打印管理软件（下称「参考产品」）做的功能盘点，结合样衣间「扫一打一」的场景逐项评级。原始盘点材料不放进仓库。

## 参考产品要点（只记对我们有意义的部分）

- **定位**：热敏标签机、面单机的打印机管理工具，主要用户是电商卖家，以及打吊牌、价签的小商家。
- **与我们同构的流程**：它的移动端「扫商品码 → 自动填价签模板 → 打印」与我们的核心流程一致，说明这类需求有市场验证。
- **我们的差异化**：扫码枪专用流程、防重门限、语音确认播报、本地全文检索的打印记录。
- **安全反例（不照搬）**：
  - 远程页面开启 `nodeIntegration`，关闭 `webSecurity`。
  - 本地服务端口不做鉴权。
  - SQL 靠字符串拼接。

## 原生能力的实现方式

读取类能力继续用系统自带命令：Windows 用 PowerShell/CIM，macOS 用 `ipptool`、`lpstat`。打印机名只通过环境变量或参数数组传入，不经过 shell。

需要调用系统 API 写设置时（自动设置驱动纸张、读取 USB 打印机状态），用 **C++ Node-API 原生模块**，不用独立的命令行程序：

- **ABI 稳定**：Node-API 跨 Electron 版本二进制兼容，升级 Electron 不用重新编译。
- **构建与打包**：CI 在 Windows 和 macOS 上预编译 `.node`；打包时放进 `asarUnpack`，不需要 `npmRebuild`。
- **接口**：只暴露窄接口。每个函数只做一件事，参数在 JS 侧先校验。
- **平台 API**：Windows 调 winspool（`AddForm`、`DocumentProperties`、`SetPrinter`），macOS 调 CUPS API。
- **测试**：纯逻辑留在 TypeScript 里用单元测试覆盖，原生层只做系统调用，在真机上验证。
