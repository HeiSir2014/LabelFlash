# CDL-云签速印 通用识别规则与通用模板 设计

- 日期：2026-09-28
- 版本：与 Phase 1 的全部功能一起，作为第一个正式版本 **1.0.1** 发布（全部完成后再发，不单独发 0.x 版本）。本功能在分支 `feature/generic-scan-rules` 上开发，完成后并入 `feature/phase1-desktop-client`。
- 上位规格：`docs/superpowers/specs/2026-09-28-label-flash-design.md`

## 1. 背景与目标

Phase 1 只认「编码-颜色-尺码」一种二维码：识别规则写死成一个正则，模板字段也固定为编码、颜色、尺码、完整编码。纯数字订单号、其他分隔符、多行内容一律判为「格式不对」。

本项目开源，面向多个厂家。目标：

1. **可配置的识别规则**：内置常见规则；界面上可以新建、排序、启用或停用；规则可以导出成 JSON 文件分享，也可以导入。
2. **通用模板**：内置一套能显示任意字段的「通用」模板，作为默认模板；每条规则可以绑定自己的模板。
3. **二维码内容可配置**：默认是扫到的原始内容，也可以改成某个字段或一段带变量的文本。
4. **多行扫码**：扫码枪把二维码里的换行当成回车发出来，程序要把整段多行内容当成一次扫码。

不做：在标签上印条形码（一维码）——扫码枪扫条形码得到的文字照常按规则识别；JavaScript 脚本规则（执行陌生代码，不安全）；云端规则库。

## 2. 识别

### 2.1 识别结果

```ts
interface ScanField { name: string; value: string }
interface ScanResult {
  raw: string;         // 规范化后的原始内容，也是防重复的依据
  ruleId: string;
  ruleName: string;
  fields: ScanField[]; // 有序，字段名在同一结果里唯一
}
```

`raw` 的规范化规则：
- 换行统一为 `\n`，去掉首尾空白。
- 允许换行和制表符，其他控制字符和不可见字符（零宽字符、BOM 等）一律拒绝。
- 长度上限 1000 字符。

### 2.2 规则类型

规则定义是纯数据，可以导出和分享。四种类型：

| 类型 | 配置 | 匹配 |
|---|---|---|
| 分隔符拆分 `delimited` | 分隔符（1–3 个字符，可选「换行」「制表符」）；各段字段名（2–10 个）；多出的分隔符并入第几个字段 | 段数不够则不匹配；段数多了，多出来的分隔符并入指定字段；每段去掉首尾空白后都不能为空 |
| 多行键值 `keyValue` | 键值分隔符（默认 `:` `：` `=`）；字段列表（字段名 + 别名）；必填字段；是否保留未登记的键 | 逐行按第一个分隔符拆开；键名不区分大小写地对照别名；必填字段齐了才算匹配 |
| 整段 `whole` | 字段名；字符集（纯数字 / 字母加数字 / 不限）；长度范围 | 整段内容就是一个字段；字符集为「不限」时才允许多行 |
| 正则 `regex` | 正则（不超过 300 字符，至少一个命名分组）；可选标志 `i` `m` `s` `u` | 命名分组就是字段；在隔离环境里执行，超过 20ms 视为不匹配 |

- **匹配顺序**：按规则顺序逐条尝试，第一条匹配的生效。
- **兜底规则**：最后一条是内置的「原样打印」，把整段内容作为「内容」字段，可以关掉。关掉后，没有规则匹配的码提示「没有匹配的识别规则」，语音播报「无法识别，请检查扫码内容」。

### 2.3 内置规则

内置规则只读，要修改先复制成自定义规则。

1. **横杠三段**（`builtin:dash-three`）：分隔符 `-`，字段依次为编码、颜色、尺码，多出的横杠并入「编码」。用当前模板（1.3.0 之前默认绑定「样衣标准」，见 4.4 节）。
2. **纯数字订单号**（`builtin:digits-order`）：整段匹配，纯数字，8–30 位，字段名「订单号」。
3. **多行键值**（`builtin:key-value`）：登记的常见键及其别名：
   - 订单号：订单编号、单号、Order、Order No
   - 款号：货号、编码、Style、SKU
   - 颜色：Color
   - 尺码：Size
   - 数量：Qty

   至少要识别出一个已登记的键，未登记的键也保留。
4. **原样打印**（`builtin:raw`）：整段匹配，字符集不限，字段名「内容」。

### 2.4 每台电脑的规则设置

规则定义（可分享）和本机设置（不导出）分开存。本机设置保存在 `AppSettings.ruleSettings: { id, enabled, templateId | null, templateRoutes }[]`，数组顺序就是匹配顺序：
- 读取时丢掉已不存在的规则，并在末尾补上新增的内置规则。
- `templateId` 为 null 时用当前模板；绑定的模板被删除后同样退回当前模板。
- `templateRoutes`（按字段换模板）：每条是「字段 包含 / 等于 值 → 模板」，在加工步骤之后按字段判断，第一条命中的生效，都不命中时用 `templateId`。详见面单模板设计文档第 6 节。

### 2.5 正则的安全执行

- **隔离执行**：正则在 `node:vm` 的独立上下文里执行，超时 20ms 就中断，当作不匹配，并记日志。已实测 Electron 44 的 Node 和 Bun 都能在超时后打断灾难性回溯。
- **只在主进程识别**：渲染层通过 IPC 调用，渲染层不执行规则。

### 2.6 导入导出

- **文件格式**：`{ "format": "cdl-labelflash-rules", "version": 1, "rules": [...] }`，只包含规则定义。
- **导出**：导出单条规则（规则卡片上的「导出」），或全部自定义规则。
- **导入**：
  - 文件不超过 256KB，最多 50 条规则。
  - 每条逐项校验；无效的规则跳过，并说明原因。
  - 有效的规则一律作为新的自定义规则加入（生成新 id），默认启用，排在「原样打印」之前。
  - 含 HTTP 查询步骤的规则导入后**默认停用**，导入结果里列出它会访问的域名；用户确认后手动启用。否则一份分享来的规则文件就能把扫码内容发到任意服务器。
  - 查找表的数据不随规则导出（可能很大，也可能是内部数据），另有表格的导入导出；导入的规则引用了本机没有的表时，这一步查不到结果。
- **文件对话框**：由主进程打开；渲染层只拿到结果摘要。

### 2.7 加工步骤

识别只负责把内容拆成字段；很多场景还要**生成新字段**：把数字编码拼成 URL 放进二维码、去掉前缀、按编码查货架号印在尺码下面、调用接口查订单数据。

- **位置**：扫码 → 识别规则拆出字段 → 这条规则的加工步骤依次执行 → 模板。
- **挂在规则上**：每条规则可以有最多 10 个步骤（`steps`），随规则导出分享。内置规则没有步骤；要加工就复制成自定义规则。
- **每一步产出字段**：步骤按顺序执行，后面的步骤可以用前面产出的字段；产出的字段名与已有字段相同时覆盖原值（位置不变），否则追加到末尾。模板、备注、二维码内容把它们当普通字段用。
- **不用脚本**：步骤都是填表式配置，不让用户写代码。操作员不会写代码；`node:vm` 不是安全边界，规则文件又能跨厂家分享；四种步骤已覆盖绝大多数需求。以后确实需要复杂逻辑时，再考虑在 QuickJS（WASM）里跑「输入字段 → 输出字段」的纯函数，不能联网，限制内存和时间。

| 步骤 | 配置 | 例子 |
|---|---|---|
| 文本拼接 `template` | 输出字段、文本（支持 `{字段名}` `{完整内容}` `{规则}` `{日期}` `{时间}`） | `https://example.com/o/{订单号}` → 「链接」 |
| 正则替换 `regexReplace` | 输入字段（或完整内容）、正则、标志、替换文本（`$1`、`$<名字>`）、输出字段 | 去掉前缀 `^SO-` |
| 查找表 `lookup` | 输入字段、表格、按哪一列匹配、要取的列 → 输出字段 | 编码 → 货架号 |
| HTTP 查询 `http` | 方法、地址、请求头、请求体、超时、从返回的 JSON 取值 → 输出字段、失败时怎么办 | 按编码查货架号 |

- **正则替换**：和识别规则一样在隔离环境里执行，超时 20ms；不匹配时输出原值。
- **查找表**：
  - 表格从 CSV 导入（先按 UTF-8 严格解码，带或不带 BOM；不是合法 UTF-8 时按 GB18030 解码，兼容中文 Excel 默认的 GBK；第一行是列名），存本机 SQLite；最多 20 张表，每张表最多 10 万行、20 列，文件不超过 20MB。
  - 精确匹配，匹配前去掉首尾空白；可以选择忽略大小写。
  - 查不到时输出字段为空。
- **HTTP 查询**：
  - 只在主进程执行，只允许 `http:` 和 `https:`；地址、请求头、请求体里的变量按 URL / JSON 规则转义。
  - 超时默认 1500ms，最长 5000ms；返回内容不超过 256KB，必须是 JSON。
  - 取值用简单路径：`data.shelf`、`items[0].name`。
  - 密钥（例如接口令牌）单独保存在本机，用系统加密存储（Electron `safeStorage`），在请求头里用 `{密钥:名称}` 引用；密钥不随规则导出，也不会出现在日志里。
  - 相同请求在有效期内（默认 60 秒，可设 0–3600 秒）用缓存结果：扫码预览时查一次，打印时直接用缓存。
  - 失败（超时、网络错误、非 2xx、返回不是 JSON、取不到值）时二选一：
    - 照常打印，输出字段为空（默认）。
    - 拦下不打印，界面提示「数据查询失败，没有打印」并给出原因，语音播报同一句，打印记录记为失败（`LOOKUP_FAILED`），可以直接「重试打印」。
- **失败与空值**：步骤没有产出时，输出字段为空字符串；模板里空字段不显示，备注里的 `{字段名}` 展开为空。
- **防重复**：仍按原始内容判断，与加工结果无关。
- **预览**：扫码后预览区照常显示；有 HTTP 步骤时状态栏先显示「正在查询…」。

### 2.8 打印结果通知

每次打印的最终结果发给下游系统（ERP、仓库系统、群机器人），用来通知和记录后续状态。

- **接口**：设置里最多 5 个，每个有名称、地址（http/https）、签名密钥、勾选的事件、是否启用。本机设置，不随规则导出。
- **事件**：`printed`（已打印，含补打和记录重打）、`failed`（含查询失败）、`duplicate`（重复被拦截）、`invalid`（无法识别）；默认只勾选已打印和失败。测试页不发通知。
- **请求**：`POST`，`Content-Type: application/json`，请求体：

  ```json
  {
    "id": "打印记录 id（事件编号，接收方靠它去重）",
    "event": "printed",
    "occurredAt": "2026-09-28T01:05:00.000Z",
    "raw": "原始内容",
    "rule": { "id": "builtin:dash-three", "name": "横杠三段（编码-颜色-尺码）" },
    "fields": { "编码": "CL5640-TK", "颜色": "图片色", "尺码": "XL" },
    "printer": "打印机名称",
    "paper": "100x180",
    "source": "desktop",
    "forced": false,
    "failureReason": null,
    "station": { "name": "电脑名称", "app": "1.0.1" }
  }
  ```

  识别不了时 `rule` 和 `fields` 为 null。`paper` 是这一张的纸张（宽x高，毫米），支持多种纸张后新增；旧记录和识别不了的记录为 null。`source` 是 `desktop`（扫码枪）、`history`（记录重打）、`mobile`（手机）、`api`（本机接口）、`batch`（批量打印）、`pdf`（PDF 打印）或 `ipp`（局域网共享）；本机接口打的不经过识别规则，`rule` 固定为 `{ "id": "api", "name": "本机接口" }`，`fields` 是调用方给的字段；批量打印的 `rule` 固定为 `{ "id": "batch", "name": "批量打印" }`，`fields` 是这一行对出来的字段（含序号）；PDF 打印的 `rule` 固定为 `{ "id": "pdf", "name": "PDF 打印" }`，`fields` 是「文件」「页码」「第几张」；局域网共享的 `rule` 固定为 `{ "id": "ipp", "name": "局域网共享" }`，`fields` 是「文件」（对方的任务名）「页码」「第几张」「电脑」，对方给了用户名时还有「用户」。
- **签名**：请求头 `X-LabelFlash-Event`、`X-LabelFlash-Delivery`（事件编号）、`X-LabelFlash-Timestamp`（Unix 秒）、`X-LabelFlash-Signature: sha256=<hex>`。签名是 `HMAC-SHA256(密钥, 时间戳 + "." + 请求体)`；接收方用同一个密钥验证，并拒绝时间戳相差超过 5 分钟的请求（防重放）。密钥用 `safeStorage` 加密保存，界面上只能重新设置、不能查看。
- **可靠投递**：
  - 打印结果先写进本机 SQLite 的发送队列（`webhook_deliveries`），后台发送，不阻塞打印。
  - 2xx 算成功；超时 5 秒；网络错误、超时、5xx、408、429 按 1 分钟、5 分钟、30 分钟、2 小时、12 小时退避重试；其他 4xx 不重试（配置错误，重试也没用）。
  - 软件重启后继续发送未完成的；超过 24 小时仍未成功就放弃，保留记录。
  - 同一接口的通知按发生顺序依次发送。
  - 发送记录保留最近 1000 条。
- **界面**：设置页「打印结果通知」：接口列表（新增、编辑、启用、删除、发送测试事件 `test`），最近的发送记录（事件、接口、结果、状态码、尝试次数、下次重试时间），失败的可以手动「立即重试」。

## 3. 多行扫码

扫码枪模拟键盘，二维码里的换行会以回车键发出，制表符以 Tab 键发出。

- **按停顿判断整段结束**：扫码框改成单行显示的 `textarea`。按下回车或 Tab 时先不提交，等一小段时间（默认 80ms）：
  - 这段时间里又有字符输入，就把刚才的回车或 Tab 作为换行或制表符写进内容，继续接收。
  - 停顿超过这段时间，才算一次扫码结束并提交。
- **可调**：设置里的「多行扫码等待时间」可调，范围 20–500ms。手动打字按回车只多等这 80ms，人感觉不到。
- **输入法**：输入法组字过程中的回车不处理。

## 4. 模板

### 4.1 字段区

二维码旁的字段区改为：

```ts
interface FieldsArea {
  mode: 'all' | 'pick';
  all: TextStyle & { showNames: boolean };  // 全部字段：按识别顺序列出，「字段名：值」
  slots: FieldSlot[];                        // 指定字段：{ field, prefix, fontSizeMm, bold }，最多 8 个
}
```

- **全部字段**：按顺序列出，放不下时先缩小字号；最多显示 6 行，超出部分用「…等 N 项」收尾。
- **指定字段**：只显示模板里挑选、且本次识别到的字段。一个都没识别到时，按「全部字段」显示，保证标签不会空白。
- **两种模式的配置都保留**：切换模式不会丢失另一种模式的配置。
- **排列**（`arrangement`，两种模式通用）：
  - 横向 `inline`：前缀一列、值一列的对齐网格，值永远对齐。
  - 垂直 `stacked`：前缀（字段名）单独一行、小一号不加粗，值在下一行，适合值较长的内容。
- **分隔符**：「全部字段」的前缀是「字段名 + 分隔符」，分隔符默认「：」，最长 3 个字符，可以清空，不能含换行。
- **文字排版算法**（打印窗口不运行脚本，只能在生成 HTML 前估算）：
  - 按字符类别估算字宽（汉字、数字、大小写字母、窄字符、横杠等），逐字模拟 `word-break: break-all` 的折行。
  - 每行先看缩小不超过 25% 能否把值放进一行，能就缩小（订单号不从中间断开），否则保持字号、允许折行。
  - 所有行加起来超过可用高度时，按同一比例整体缩小，二分查找放得下的最大比例，不低于最小字号。
  - 「全部字段」各行统一字号；「指定字段」每行按自己的字号缩放。
  - 底部整行和备注：在允许的行数内，二分查找放得下的最大字号。

### 4.2 底部整行与二维码

- **底部整行**：显示完整原始内容，多行用「 / 」连起来。只有一个字段、且它的值就是完整内容时，自动不显示，避免重复。
- **二维码内容**：
  - 三种来源：原始内容（默认）、某个字段、带变量的文本。
  - 取不到内容（字段没识别到、文本为空）时，退回原始内容。
- **二维码排布**（按热敏机点阵，默认 203dpi，1 点 ≈ 0.125mm）：
  - 模块宽度取整数个点，打出来模块宽窄一致、边缘清晰；按点阵对齐后居中放进模板给的方框。
  - 模块 2–8 个点（约 0.25–1mm）：小于 2 个点难以扫描；最多 8 个点，保证和文字之间至少 2 个模块的静区。
  - 从模板要求的容错等级开始，放不下（模块不足 2 个点）就逐级降低；降到 L 仍放不下就不印二维码，并在预览上提示。

### 4.3 备注变量

- **支持的变量**：`{任意字段名}`、`{完整内容}`、`{规则}`、`{日期}`、`{时间}`。
- **未识别的变量**：标签上（备注、二维码文本）本次没有的字段名或未知变量印成空，不印出「{货架号}」这样的原文（扫码枪扫的码没有图，货架号这一步跳过，就没有这个字段）。HTTP 查询里仍原样保留，`{密钥:名称}` 留给主进程替换。

### 4.4 内置模板

| 模板 | 字段区 | 说明 |
|---|---|---|
| 通用（二维码在左）`builtin:generic` | 全部字段 | 新的默认模板 |
| 通用（二维码在右） | 全部字段 | |
| 通用（字段名在上） | 全部字段，垂直排列 | 值较长时更易读 |
| 通用 · 大字（无二维码） | 全部字段，大字号 | 适合只看单号 |
| 通用 · 大二维码 + 日期备注 `builtin:big-qr` | 全部字段，不显示字段名 | 二维码 30mm，旁边印日期 |
| 通用 · 小二维码 + 底部备注 `builtin:bottom-note` | 全部字段 | 二维码 18mm，底部印日期和时间 |

默认的当前模板从「样衣标准」改为「通用（二维码在左）」。

**1.3.0 把「样衣」并进「通用」**（2026-10-01 用户确认）：样衣模板和通用模板扫样衣码时打出来几乎一样（「全部字段」列出的正好是编码、颜色、尺码），区别只在「全部字段 / 指定字段」一个设置，没必要分两类。

- 内置标签模板只留上面 6 个，都用「全部字段」；货架号读到就印，字段超过 6 行时也留着它（折掉它前面的字段）。
- 内置模板都带「指定字段」的预设（编码、颜色、尺码、货架号，带前缀）：复制后切到「指定字段」就是原来样衣模板的字段行。
- 去掉的编号换到版式相同的通用模板（`currentTemplateId`）：`builtin:standard`、`builtin:plain` → `builtin:generic`，`builtin:qr-right` → `builtin:generic-qr-right`。当前模板、规则绑定、按字段换模板、本机接口的模板名读的时候都换，升级后照样打出编码、颜色、尺码。大二维码、底部备注沿用原来的编号。
- 横杠三段不再默认绑定模板，跟着当前模板走；1.2.x 存下的绑定换成 `builtin:generic`，打出来不变。

## 5. 存储

- **规则表**：`scan_rules`（id、body、created_at、updated_at，STRICT）直接写进初始 schema，和 `templates` 表的写法一致；不加迁移。
- **设置**：新增 `ruleSettings`、`scanLineGapMs`；`activeTemplateId` 的默认值改为 `builtin:generic`。
- **打印记录**：只记原始内容；重打时按当前规则重新识别和加工；全文搜索照常对原始内容建索引。失败原因新增 `LOOKUP_FAILED`（HTTP 查询失败且设为拦下）。
- **查找表**：`lookup_tables`（id、name、columns JSON、row_count、created_at、updated_at）和 `lookup_rows`（table_id、row_index、cells JSON，主键 `(table_id, row_index)`），直接写进初始 schema。查询时按「表 + 匹配列 + 是否忽略大小写」在内存里建一次索引（`LookupIndex`），替换或删除表格时失效。
- **密钥**：独立的 `secrets` 表（name、value = `safeStorage` 加密后的字节、updated_at），不放进设置——设置会整份发给界面，密文也不该出现在渲染进程。渲染层只能看到名称；系统加密不可用时拒绝保存。HTTP 查询和打印结果通知的签名密钥共用这张表。
- **HTTP 请求**：用 Electron 的 `net.fetch`（Chromium 网络栈），自动使用系统代理设置。
- **不做兼容、不做迁移**：1.0.1 是第一个发布版本，之前没有任何用户数据。开发期间的数据库和设置一律不兼容：开发机删掉旧的数据目录（Windows `%LOCALAPPDATA%\CDL-LabelFlash`，macOS `~/Library/Application Support/CDL-LabelFlash`）重新生成即可。

## 6. 界面

> 页面位置以 [配置中心](2026-09-29-config-center-layout-design.md) 为准：识别规则、查找表、密钥是配置中心里的三个页面，「规则 · 模板」显示在工作台预览工具条上。本节只规定各功能要有什么，不再规定放在哪里。

- **识别规则**：
  - **规则列表**：
    - 显示名称、类型、是否启用、绑定的模板（下拉框）。
    - 可上移下移调整顺序。
    - 自定义规则可以编辑、复制、删除；内置规则只能复制。
    - 新建规则时先选类型。
  - **规则编辑器**：按类型显示对应的表单，保存前逐项校验；下方是「加工步骤」列表，可以添加、排序、删除步骤，每种步骤一张表单。
  - **试一试**：粘贴或扫一段内容，实时显示命中哪条规则、识别出哪些字段、每个加工步骤的结果（HTTP 步骤显示耗时和错误原因）。
  - **导入 / 导出**：导入文件；导出单条规则或全部自定义规则。
- **查找表**：导入 CSV、查看列名、行数和前 20 行、替换、删除。
- **密钥**：新增、替换、删除（只显示名称，不显示内容）。
- **命中的规则**：工作台预览工具条显示这一张用的规则和模板。
- **模板编辑器**：
  - 字段区：切换「全部字段 / 指定字段」；指定字段的字段名输入框带候选列表，候选来自所有规则里出现过的字段名和预览内容识别出的字段名。
  - 二维码内容来源可选。
  - 备注变量说明同步更新。
- **打印记录**：多行内容只显示第一行，后面接「…」。
- **格式不对的提示**：改为「没有匹配的识别规则」，并提示去识别规则里新增规则，或开启「原样打印」（配置中心 §5.9 的跳转链接）。
- **正在查询**：有 HTTP 步骤时预览要等接口返回，超过 200ms 状态条先显示「正在查询…」（配置中心 §4.3）。
