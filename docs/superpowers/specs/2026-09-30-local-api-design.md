# 本机接口（HTTP）设计

- 日期：2026-09-30
- 状态：方案已确认（本机给网页和本机软件、局域网给客户端软件且默认开启、只做 HTTP、遵循 Google API 设计规范、所有打印记录完整留存）
- 目标版本：发版时确认
- 属于「把打印和排版提供给第三方」的第 2 个子项目。IPP 打印机拆成 2b，另写设计文档（见第 11 节）
- 前置：第 1 个子项目（多台打印机、多种纸张）已完成，见 `2026-09-29-multi-printer-paper-design.md`

## 1. 目标与边界

**目标**

- 第三方软件交「模板 + 字段」，程序按模板排版、按纸张决定打印机、打印，和扫码枪走同一套流程。
- 只排版：返回按模板纸张排好的 PDF。
- 一次可以提交很多张（上限 1000），逐张查询状态。
- 所有打印记录（包括扫码枪、手机）完整留存在本机 SQLite 里，为以后的数据分析、看板和导出留好数据。

**谁来调用**

| 调用方 | 从哪里来 | 授权 |
|---|---|---|
| 浏览器里的网页系统 | 只从本机（127.0.0.1） | 网站第一次调用时电脑上弹框确认，按网站记住 |
| 客户端软件、服务器程序 | 本机或局域网 | 程序密钥（`Authorization: Bearer …`） |

局域网里只考虑客户端软件，不考虑局域网里的浏览器（https 网页调用局域网里的 http 地址会被浏览器当作混合内容拦下）。

**不做**

- HTTPS：只提供 HTTP（和以后的 IPP）。局域网里传输的内容是明文，界面和文档写明。
- 云端下单、多租户：不经过我们的服务器。
- 数据分析、看板、导出：这次只把数据存全，功能另列在路线图里。

## 2. 遵循的规范

- **接口设计**：Google API 设计规范（AIP，google.aip.dev）。以资源为中心：
  - 标准方法（AIP-131 Get、132 List、133 Create）；
  - 自定义方法（AIP-136，`资源:动词`）；
  - 批量创建（AIP-233）；
  - 状态字段（AIP-216）；
  - 请求编号防重复（AIP-155）；
  - 错误格式 `google.rpc.Status`（AIP-193）；
  - 分页（AIP-158）；
  - JSON 字段用小驼峰。
- **接口描述**：OpenAPI 3.1，随程序提供（`GET /v1/openapi.json`），有测试核对它和实际接口一致。
- **浏览器访问本机**：遵循 Chrome 的「本地网络访问」（Local Network Access）规则。Chrome 142 起，公网网页访问本机会先弹浏览器自己的权限框，Chrome 145 起访问本机单独是一项权限。旧版 Chrome 的私有网络访问预检（`Access-Control-Request-Private-Network`）也照规范回复。
- **防 DNS 重绑定**：参考 Chrome 远程调试端口的做法，网页来的请求要核对 Host。
- **代码**：新代码遵循 Google TypeScript 风格指南，和仓库现有的 Biome 规则、`CLAUDE.md` 约定冲突时以仓库为准；提交按 Google 工程实践保持小而单一。

## 3. 服务与端口

- **在主进程里运行**：用 Node 自带的 `node:http`，不加新依赖。程序关着时接口不可用（本来打印也要程序开着）。
- **监听**：
  - 局域网开启（默认）：监听所有网卡（`::`，同时接受 IPv4 和 IPv6）；
  - 局域网关闭：只监听本机（`127.0.0.1` 和 `::1`）。
  - 按对方的地址区分本机和局域网：回环地址（127.0.0.0/8、::1、IPv4 映射的 127.x）算本机，其余都算局域网。
- **端口**：
  - 默认 17631。被占用时依次试 17632、17633，三个都写进接口文档，第三方可以依次尝试。
  - 用户在设置里指定了端口时，只用这一个，被占用就报错，不悄悄换成别的。
  - 都被占用：接口不启动，程序照常扫码打印。配置中心显示「端口被占用」和占用的程序名（Windows 用 `Get-NetTCPConnection` 查；查不到就不显示）。
- **自报身份**：`GET /v1/service` 不需要授权，返回产品名、接口版本和实际端口。调用方先调它，确认连的是我们，不是占着端口的别的程序。
- **限额**：
  - 请求体最大 4MB；
  - 同一调用方每秒最多 20 个请求（可以突发到 40 个），超出返回 `RESOURCE_EXHAUSTED`；
  - 排队中的标签总数最多 5000 张，超出同样拒绝，防止程序出错时刷爆打印机。

## 4. 资源和方法

所有路径在 `/v1` 下。

| 方法 | 路径 | 说明 |
|---|---|---|
| Get | `GET /v1/service` | 自报身份（不需要授权） |
| — | `GET /v1/openapi.json` | 接口描述（不需要授权） |
| List | `GET /v1/templates` | 可用模板：编号、名称、纸张、字段名 |
| Get | `GET /v1/templates/{template}` | 一个模板 |
| 自定义 | `POST /v1/templates/{template}:render` | 只排版，返回 `application/pdf` |
| List | `GET /v1/printers` | 打印机、各自负责的纸张、状态 |
| Create | `POST /v1/printJobs` | 提交一个打印任务 |
| 自定义 | `POST /v1/printJobs:batchCreate` | 一次提交多个（上限 1000） |
| Get | `GET /v1/printJobs/{printJob}` | 任务状态 |
| List | `GET /v1/printJobs` | 任务列表，新的在前，分页 |

**模板编号**：程序里的模板编号带冒号（`builtin:standard`、`custom:<uuid>`），和 AIP 自定义方法的冒号冲突。接口里把冒号换成横线（`builtin-standard`、`custom-<uuid>`），两种写法一一对应。按编号精确查找，找不到就报 `NOT_FOUND`，不退回通用模板。

**打印任务（PrintJob）**

```json
{
  "name": "printJobs/3f1c…",
  "template": "templates/custom-7a2e…",
  "fields": [{ "name": "编码", "value": "CL5640-TK" }, { "name": "尺码", "value": "XL" }],
  "content": "CL5640-TK-图片色-XL",
  "copies": 2,
  "printer": "面单机B",
  "requestId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "state": "PRINTING",
  "sentCopies": 1,
  "failure": null,
  "createTime": "2026-09-30T08:00:00Z",
  "updateTime": "2026-09-30T08:00:01Z"
}
```

- `fields`：必填，有顺序（决定「显示全部字段」时的排列），1–50 个。字段名和识别规则的字段名同样规则（1–20 个字，不能有花括号和控制字符，不能重名）；值最长 1000 个字（和扫码内容的上限一致）。
- `content`：可选，最长 1000 个字。「完整内容」，二维码选「完整内容」、底部整行、备注里的 `{完整内容}` 用它；不给时用字段拼成「名称：值」一行一个。
- `copies`：1–100，默认 1。每一份都是一条打印记录。
- `printer`：可选。指定时必须是这台电脑上的打印机，不在就报 `FAILED_PRECONDITION`，不退回纸张分配。不指定时按模板决定（模板指定 → 纸张分配）。
- `requestId`：可选，UUID。同一调用方、同一 `requestId` 在 24 小时内重复提交，直接返回已有的任务，不再打印（AIP-155）。
- `state`（AIP-216）：`QUEUED` → `PRINTING` → `SENT`（全部份数都已发送打印）或 `FAILED`。
  - 用 `SENT`，不说「已打印」：驱动回调成功只代表进了打印队列，和界面用词一致。
  - 失败时 `failure` 是 `{ "reason": "NO_PRINTER", "message": "中文说明" }`。可能的原因：`NO_PRINTER`、`PRINTER_NOT_FOUND`、`PRINTER_NOT_READY`、`PRINT_TIMEOUT`、`PRINT_ERROR`。某一份失败时任务就是 `FAILED`，`sentCopies` 写明已经发送了几份；后面的份数不再打。
  - 重复提交（同一 `requestId`）不算失败：直接返回已有的任务。
- **Create 返回 200** 和状态为 `QUEUED` 的任务（AIP 标准方法返回资源本身），之后查询状态。
- **batchCreate**（AIP-233）：请求 `{ "requests": [ {…}, … ] }`，返回 `{ "printJobs": [ … ] }`，顺序和请求一致。整批先校验，有一个参数不对整批都不收，错误里指出是第几个（`requests[12].fields`）。收下之后每张各自成功或失败。

**只排版**：`POST /v1/templates/{template}:render`，请求 `{ "fields": [...], "content": "..." }`，返回 `application/pdf`。

- 页面尺寸是模板的纸张。
- 二维码是矢量图，不按某台打印机的点对齐：模块按毫米算，最小 0.25mm。
- 用 Electron 的 `printToPDF` 生成，和打印共用同一份标签 HTML。

**分页**：`pageSize` 默认 50、最大 1000，`pageToken` 是不透明的字符串。

**错误**（AIP-193）：

```json
{
  "error": {
    "code": 404,
    "status": "NOT_FOUND",
    "message": "找不到模板 custom-7a2e…：请先用 GET /v1/templates 查看可用的模板",
    "details": [
      { "@type": "type.googleapis.com/google.rpc.ErrorInfo", "reason": "TEMPLATE_NOT_FOUND", "domain": "labelflash" }
    ]
  }
}
```

- 参数错误附 `google.rpc.BadRequest` 的 `fieldViolations`。
- `message` 用中文，写清怎么改。
- HTTP 状态码按 AIP-193 对应：400、401、403、404、409、413、429、500、503。

## 5. 授权和安全

**程序密钥**

- 在配置中心「本机接口」页生成，可以有多个，每个有名称（例如「ERP 服务器」），可以改名、撤销。
- 密钥只在生成时显示一次。程序只保存它的 SHA-256 摘要，用来核对，不保存原文，也不写进日志。
- 调用方式：`Authorization: Bearer <密钥>`。本机、局域网的程序都用它。
- 打印记录里记下是哪个密钥提交的。

**网站授权**（只对本机来源、带 `Origin` 请求头的浏览器请求）

1. 浏览器自己的「访问本机」权限框：由 Chrome 控制，文档里写明，网页要处理用户拒绝的情况。
2. 我们的授权：没授权过的网站先收到 `PERMISSION_DENIED`（原因 `ORIGIN_NOT_AUTHORIZED`，附「请在电脑上点允许」），同时电脑上弹出系统对话框「网站 https://erp.example.com 想使用打印服务：允许 / 拒绝」，并把主窗口带到前面。
   - 同一个网站同时只弹一个框。
   - 拒绝后 10 分钟内不再弹，直接拒。
3. 允许后记住这个网站，网页重试即可。配置中心可以撤销。

`Origin` 由浏览器填写，可信；本机的其他程序也能伪造它，但本机程序本来就能直接操作这台电脑，所以这里只防网页，不防本机程序。

**防护**

- **Host 核对**（防 DNS 重绑定，只对网页来的请求）：Host 必须是 `127.0.0.1`、`localhost` 或 `[::1]` 加端口，否则拒绝。带有效密钥的程序请求不核对 Host，局域网程序可以用机器名访问。
- **跨域**：只对已授权的网站返回允许跨域的响应头。预检请求按规范回复，并回复 `Access-Control-Allow-Private-Network: true`，兼容旧版 Chrome。
- **局域网来源只认密钥**：局域网来的请求即使带着 `Origin` 也不算网页授权。
- **局域网已开启但还没有密钥**：局域网请求一律拒绝（`UNAUTHENTICATED`），回复里说明先在配置中心生成密钥。
- **不需要授权的只有两个**：`/v1/service` 和 `/v1/openapi.json`。

**防火墙**

- **Windows 安装包**：安装界面多一个默认勾选的选项「允许局域网里的其他电脑连接打印服务」。
  - 勾选时弹一次 UAC 管理员确认，加一条入站规则：只放行本程序（按程序路径），只在专用、域网络生效，不对公共网络开放。
  - 自动更新后路径不变，不再弹框。
  - 不勾选或拒绝 UAC 时，安装照常完成，由 Windows 在首次监听时自己弹框。
  - 卸载时删掉这条规则（同样要管理员确认；更新时跑的旧版卸载程序不删）。
- **配置中心「本机接口」页**：Windows 上检测这条规则是否存在；不存在时显示「添加防火墙规则」按钮，点了弹 UAC。
- **macOS 的 pkg 安装脚本**：以管理员身份运行，顺带把程序加进系统防火墙的允许列表（`socketfilterfw --add`），只在用户打开了防火墙时起作用。
- **安装方式的说法**：根目录 CLAUDE.md 里「按当前用户安装，不需要管理员权限」改为「安装本身不需要管理员；添加防火墙规则时问一次管理员，可以拒绝」。

## 6. 打印流程

```
请求 → 授权 → 校验（整批）→ 查模板（精确）→ 建任务（QUEUED）
     → 每一份：PrintService.printFields → 决定打印机（模板指定 → 纸张分配，或调用方指定）
       → 防重复（requestId）→ 排队打印 → 写打印记录（来源 api）→ 发打印结果通知
     → 任务状态 PRINTING → SENT / FAILED
```

- **入口**：`PrintService` 新增公开方法 `printFields`，把第 1 个子项目拆出来的 `printLabel` 包装成对外的入口。它不经过识别规则，也不执行加工步骤，因为字段由调用方给出。
  - 识别结果按固定写法构造：规则编号 `api`、规则名「本机接口」，备注变量 `{规则}` 显示为「本机接口」。
- **防重复**：本机接口不用扫码内容的防重复窗口，和扫码枪、手机互不影响；靠调用方的 `requestId` 防重复（24 小时）。
- **模板**：不叠加工作台「备注」下拉框的选择。
- **没有打印机**：任务 `FAILED`（`NO_PRINTER`），和桌面端一样不写打印记录。
- **播报**：接口打的标签不播报，只刷新打印记录，和手机扫码一样，因为提交的人不在电脑前。打印机缺纸、离线照常弹系统通知。
- **队列**：同一台打印机按提交顺序打印，不同打印机之间并行（沿用现有的每台一个队列）。

## 7. 数据

**打印记录表 `jobs` 重建**（第 3 条迁移，第 1 个子项目推迟到这里的那一次）

SQLite 不能原地修改取值检查（CHECK），做法是：建新表 → 复制数据 → 删旧表 → 改名 → 重建索引、全文索引和触发器，都在一个事务里。旧数据一条不丢，序号不变，迁移测试覆盖。

| 列 | 变化 |
|---|---|
| `source` | 取值加上 `api` |
| `fields` | 新增，JSON。这一张实际打出来的字段，所有来源都存：扫码枪和手机存识别、加工后的字段，本机接口存调用方给的字段。识别不了的为空 |
| `raw` | 不变。完整内容：扫码是扫到的原文，本机接口是调用方给的 `content` 或拼出来的内容（全文搜索照常） |
| `caller` | 新增。谁提交的：本机接口为 `key:<密钥编号>` 或 `origin:<网站>`；其他来源暂时为空 |
| `paper`、`template_id` | 第 1 个子项目加的，保留 |

- 保留条数沿用设置里的「打印记录保留」（默认 10 万条，最多 100 万条）。
- 字段是 JSON，时间、来源、打印机、纸张、模板都是单独的列，便于以后统计。
- **隐私**：面单字段里有收件人姓名、电话、地址，会长期留在本机的数据库里。配置中心「本机接口」页和 README 写明；以后做导出时，可以加上按字段打码的选项。

**新表**

| 表 | 内容 | 保留 |
|---|---|---|
| `api_jobs` | 任务编号、调用方、`requestId`、模板、份数、已发送份数、指定的打印机、状态、失败原因和说明、创建和更新时间 | 7 天。标签内容以打印记录表为准，不在两处各存一份 |
| `api_job_records` | 任务 → 打印记录（每一份一条） | 跟随 `api_jobs` |
| `api_keys` | 编号、名称、SHA-256 摘要、创建时间、最后使用时间 | 撤销时删除 |

**设置里新增**

| 设置 | 默认 |
|---|---|
| `apiPort` | null（用 17631，被占用时依次试 17632、17633） |
| `apiLanEnabled` | true |
| `apiAuthorizedOrigins` | [] |

**重打**：打印记录里有模板和字段的（本机接口打的）按当时的模板、字段和内容重打，不重新识别；打印机仍按现在的分配决定。扫码的记录照旧按内容重新识别。

## 8. 界面

- **配置中心「集成」下新增「本机接口」页**：
  - **状态**：正在监听的地址（`http://127.0.0.1:17631`、`http://192.168.x.x:17631`）；端口被占用时的说明和占用的程序；防火墙规则是否存在，以及「添加防火墙规则」按钮（Windows）；

  - **接口文档**：打开 `openapi.json`，并链接到接入说明；

## 10. 测试与验收

**单元测试**（纯逻辑，`bun test`）

- 路由和参数校验；错误按 AIP-193 格式；HTTP 状态码对应。
- 授权：
  - 密钥核对、撤销后立即失效；
  - 网站授权的「等待确认 → 允许 → 撤销」；
  - 局域网来源只认密钥；
  - 局域网已开启但没有密钥时拒绝。
- 安全：Host 核对、跨域和预检的响应头、请求速率限额、排队上限。
- 任务：状态依次变化；`requestId` 24 小时内只处理一次；各种失败原因；整批校验。
- 端口：默认端口被占用时试备用端口；用户指定的端口被占用时报错。
- 数据库：第 3 条迁移（旧记录一条不丢，序号、全文搜索照常）；新表读写；`api_jobs` 7 天清理。
- 重打：接口记录按当时的模板和字段重打。
- OpenAPI 描述和实际路由一致。

**集成测试**：接口服务不依赖 Electron，用 `bun test` 真的启动 HTTP 服务，配合假打印机，从请求一路走到打印记录。

**E2E**（构建版程序 + 假打印机）

- 本机程序带密钥：单张打印；批量 300 张按纸张分到两台打印机，查询状态直到全部 `SENT`；打印记录里的来源、调用方、字段正确。
- 只排版：`:render` 返回 PDF，页面尺寸是模板的纸张。

- 配置中心「本机接口」页：生成和撤销密钥、开关局域网、端口被占用的提示。
- 打印记录重打一条接口记录。
