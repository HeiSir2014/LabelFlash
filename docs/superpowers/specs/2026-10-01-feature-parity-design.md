## 2. 共同原则

- **所有入口走 `PrintService`**：批量、PDF、IPP、远程打印都是新的「来源」（`batch`、`pdf`、`ipp`、`remote`），照常决定打印机、排队、写打印记录、发打印结果通知；记录能搜、能重打。
- **只有黑白**：热敏标签机没有灰色。图片、PDF 都按打印机分辨率转成黑白（阈值或抖动），预览里看到的就是打出来的样子。
- **对齐打印点**：位置、线、条码模块、二维码模块都取整数个打印点（沿用面单的做法）。
- **新增依赖**（都只在主进程或构建时用，bundle 仍然自包含，由 `verify:bundle` 把关）：

  | 依赖 | 许可 | 用途 | 为什么不自己写 |
  |---|---|---|---|
  | `bwip-js` | MIT | 条码编码（只用 `raw()` 取条空宽度和二维码点阵，画法自己来） | 100 多种码制，EAN / UPC 校验、DataMatrix、PDF417 自己写既大又容易错 |
  | `read-excel-file` | MIT | 读 `.xlsx` | 只读、体积小；CSV 用现有解析器（含 GBK） |
  | `pdfjs-dist` | Apache-2.0 | 把 PDF 页渲染成位图 | PDF 渲染不可能自己写 |
  | `bonjour-service` | MIT | 局域网广播打印机（DNS-SD） | mDNS 协议细节多，各平台兼容性问题已被它解决 |

  实施计划里用 context7 核对每个库的当前版本和 API；`.xls`（97-2003）不支持，提示另存为 `.xlsx` 或 CSV。

## 3. 子项目 1：标签设计器

### 3.1 模型

```
CanvasTemplate { kind: 'canvas', id, name, paper, printer, elements: CanvasElement[] }
```

- **每个元素**：`id`、`name`、`x`、`y`、`width`、`height`（mm），`rotation`（0 / 90 / 180 / 270），`locked`。数组顺序就是上下层，后面的在上面。
- **文字** `text`：内容（可含 `{字段名}`、`{序号}`、`{日期}`、`{时间}`），字号、加粗、水平 / 垂直对齐，放不下时：缩小（默认，最小原字号 60%）→ 折行 → 截断加「…」；反白。
- **条码** `barcode`：码制（下拉列常用的 10 种：Code128、EAN-13、EAN-8、UPC-A、UPC-E、Code39、Code93、ITF-14、库得巴、GS1-128；「更多」里是 bwip-js 支持的其余码制，含 DataMatrix、PDF417）；内容；号码印在下面（开 / 关、字号）。
- **二维码** `qr`：内容、容错（和现在的标签一致，`qrcode` 编码）。
- **图片** `image`：PNG / JPEG 原图（单张 ≤ 1MB，整个模板 ≤ 4MB），转黑白方式（阈值 + 阈值大小 / 抖动），等比放入框内。
- **线** `line`：横或竖，粗细，实线 / 虚线。
- **矩形** `rect`：边框粗细（0 = 无边框）、填黑、圆角。
- **表格** `table`：行高、列宽（mm）、边框粗细，每格文字（可含变量）、字号、加粗、对齐；不合并单元格。
- **限制**（`CANVAS_LIMITS`，每项写取值依据）：元素 ≤ 100、文字 ≤ 500 字、表格 ≤ 20 行 × 10 列、最小字号 1.5mm、线 ≥ 0.25mm。

### 3.2 分层

| 层 | 文件 | 作用 |
|---|---|---|
| core | `templates/canvas-model.ts`、`sanitize-canvas.ts`、`canvas-layout.ts`、`templates/mono-image.ts` | 模型和限制；校验（不合法回到默认值，超出纸张的元素收进纸内）；展开变量、排文字（复用 `fitParagraphs`）、取整到打印点；`mono-image.ts` 是灰度像素（编辑器在 1b 的 sandbox 页面里解码图片文件后存进模板）→ 黑白点的纯函数（缩放、阈值 / Floyd–Steinberg 抖动、编成 1 位 BMP），不碰图片文件本身，主进程和测试都能直接用 |
| main | `printing/canvas-html.ts`、`printing/barcode.ts` | 画 HTML（绝对定位，mm）；`barcode.ts` 统一出条码的画法和限制（bwip-js `raw()` → 按打印点画 SVG）；面单保留自己的 Code128 编码器，只共用这里的画法和限制，输出逐字不变（快照把关）；图片按 `mono-image.ts` 转黑白后编成 1 位 BMP 嵌进 HTML（不是 SVG 路径：抖动照片的黑白点交替密集，路径字符串能到几 MB，BMP 只随点数线性增长） |
| renderer | `components/canvas-editor/*`、`lib/canvas-edit.ts`（及 `canvas-snap`、`canvas-history`、`canvas-table`、`canvas-view`、`gray-image`） | 三栏编辑器；移动、缩放、对齐、等距、吸附、撤销重做、复制粘贴、表格行列、图片转灰度都是 `lib/` 里的纯函数，有单元测试；图片文件在页面里解码，模板里只存灰度像素 |

`renderLabelHtml` 按 `kind` 分派到 `canvas-html`；预览、打印、PDF 共用同一份 HTML。

### 3.3 编辑器（经典三栏，用户选定）

- **入口**：模板页「新建自由设计模板」（空白、60×40，进设计器后在右栏改纸张），或复制内置的吊牌示例；自定义的自由设计模板点「编辑」进设计器。
- **顶部**：撤销、重做；复制、粘贴、删除；对齐（左中右、上中下：选一个时对齐到安全区，选几个时对齐到它们的外框）、等距（选三个以上）；置顶、置底；网格、吸附开关；缩放（缩小、放大、适合窗口，Ctrl+滚轮）；预览内容（默认最近一次扫码，可自填；配置中心里扫码也填进来）。
- **左**：7 种元素，点一下放到画布中间，或拖到画布上松手的位置。
- **中**：毫米标尺、1mm 网格、安全边距虚线（纸边往里 1.5mm）。画布是**真实打印 HTML**（和模板页预览同一条路，草稿变了 150 毫秒后重新排版），上面一层透明覆盖层画选框、控制点、参考线和框选；拖动时只动覆盖层，松手才改模板、重新排版。所见即所打。
- **右**：没选中时是模板的名称、纸张、打印机；选中一个时是它的属性（位置、大小、旋转、锁定 + 本类设置，「插入字段」下拉）；选中几个时提示能做的操作。下面是图层列表（上层在前，只用来点选，Shift 加选）。
- **底部**：打印前检查（见 3.4）；操作条「放弃修改」「打印一张试试」「保存模板」。「打印一张试试」按预览内容打印没保存的草稿，和预览一样识别、加工，不写打印记录、不占防重复窗口。
- **键盘、鼠标**：点选、Shift 加选、框选（碰到就算）；方向键 0.1mm、Shift+方向键 1mm；Delete / Backspace 删除；Esc 取消选中（没选中时照常返回列表）；Ctrl+C / V（设计器自己的剪贴板：页面没有系统剪贴板权限）；Ctrl+Z / Y（最多 100 步，同一个输入框连续输入、连续按方向键各算一步）；Ctrl+滚轮缩放；双击文字把焦点放进右栏的「内容」框。拖动吸附到纸边、安全边距、纸的中线、其他元素的边和中线（网格只显示，不吸）。锁定的元素不能拖动、缩放、删除。
- **扫码不受影响**：画布是可聚焦的区域，不是输入框；它只处理方向键、Delete、Esc 和 Ctrl 组合键，字母数字照常被当作扫码送进「预览内容」。

### 3.4 替用户守住的底线（打印前检查，列在底部，不挡保存）

1. 元素超出安全边距：「靠近纸边，可能打不全」。
2. 条码：模块对齐打印点、两侧留 10 个模块空白；放不下、内容不合码制（例如 EAN-13 位数不对、校验位错、有中文）就不印，并说明原因。
3. 二维码放不下：降容错，仍不行就不印并说明。
4. 字段这一张没有：这一项不印（和面单一样）。
5. 文字缩到最小仍放不下：截断并提示。
6. 图片太大：选图时按像素上限（单张 1MB 灰度像素、边长 4000）缩小后存；文件超过 20MB 不读；整个模板的图片超过 4MB 不插入，并说明上限。

### 3.5 和现有功能的关系

自由设计模板和标签、面单模板一样：能设为当前模板、被规则绑定、被按字段换模板选中、有自己的纸张和打印机；本机接口 `GET /v1/templates` 列出它用到的变量；批量打印直接用。内置示例模板放进子项目 2。

## 4. 子项目 2：模板库

- **内容**：约 20 个内置自由设计模板，分 7 类：服装吊牌（3）、价签（3）、商品条码（EAN-13 / Code128，3）、鞋盒标（2）、食品标签（品名、配料、生产日期、保质期，2）、珠宝 / 小商品尾巴标（2）、仓储（货架 / 库位、资产标签、箱标，各 1）。纸张覆盖 30×20、40×30、50×30、60×40、70×50、100×100、100×150。
- **界面**：配置中心「模板」页加「从模板库新建」：左边分类，右边缩略图（就是真实排版的预览），按纸张筛选；点「用这个模板」复制成自定义模板并进入设计器。
- **字段名约定**：模板库统一用「品名、编码、颜色、尺码、价格、商品码、生产日期、保质期、货架号」等中文字段名，和内置识别规则、批量打印的列名自动对应。
- **测试**：每个模板的快照、视觉验收逐个截图、E2E 抽一个从模板库新建并打印。

## 5. 子项目 3：批量打印

- **入口**：工作台标题栏加「批量打印」，打开全窗口的批量打印页（和配置中心同级）；配置中心里不打印的规则不变。
- **步骤**（一页里自上而下，不是多步向导）：
  1. **选模板**（任意一类）。
  2. **数据**：导入 `.xlsx` / `.csv`（拖进窗口也行），或者在表格里直接粘贴（从 Excel 复制），或者不用数据、只按序号打 N 张。第一行是表头；最多 10,000 行。
  3. **对列**：模板用到的每个变量对一列（按列名自动对上，对不上的标红，可手动选或填固定值）。
  4. **序号** `{序号}`：前缀、起始、步长、位数（补零）、后缀；也可以对到数据里的一列。
  5. **份数**：每行固定几份，或对到数据里的「份数」列。
  6. **预览**：左边数据表（可勾选要打的行、搜索），右边当前行的真实预览，上一张 / 下一张；有问题的行（缺字段、条码不合法）标黄，汇总在顶部。
  7. **打印**：进度条（已发送 / 总数）、暂停、继续、取消；失败的行可以单独重打；不受防重复窗口影响。
- **实现**：主进程 `batch/`：读文件（`read-excel-file`、现有 CSV 解析）→ 行 → `PrintService.printFields`（来源 `batch`，带批次号）；每台打印机一个串行队列（现有），批量任务按行依次入队，进度经 IPC 推给界面。core 里放纯逻辑：列名匹配、序号生成、份数展开、行校验，各有单元测试。
- **记录**：每张一条打印记录，来源「批量」，带批次号和行号；打印记录里可以按批次筛选、整批重打失败的。
- **本机接口**：已有的批量提交不变。

## 6. 子项目 4：PDF 打印

- **入口**：工作台「打印 PDF」（也可以把 PDF 拖进窗口）。
- **渲染**：主进程开隐藏窗口（sandbox，只加载本程序的页面）用 `pdfjs-dist` 把每页按目标打印机分辨率渲染成位图；最多 200 页、单个文件 ≤ 50MB。
- **裁切方式**（自动识别，可改）：
  1. **整页**：整页缩放到纸张（按纸张方向自动旋转）。
  2. **去白边**：找内容的外框，裁掉四周空白再缩放（跨境面单常见）。
  3. **一页多张**：按大片空白或分割线把一页切成几块（例如 A4 上 2×2 四张面单），每块一张标签。
  4. **手动框选**：在第一页上画一个或几个框，后面每页按同样的位置裁（固定格式的平台导出件）。
- **输出**：每块 → 黑白位图（阈值 / 抖动）→ 放进按纸张生成的标签 HTML → 照常打印。预览是全部块的缩略图网格，可以删掉不要的、调整顺序、设份数。
- **记录**：来源「PDF」，记文件名和页码 / 块号；重打从记录里找回同一块（打印时缓存的黑白位图保留 7 天）。
- **纯逻辑**（core / 主进程不依赖 Electron 的文件）：内容外框检测、空白分割、旋转判断、缩放计算，用合成的位图做单元测试。

## 7. 子项目 5：打印机管理

### 7.1 标签机指令

- 打印机页每台打印机加「指令集」：自动（默认，按在线识别表 + 驱动名猜）/ TSPL / ZPL / EPL / 不发指令。
- **下发**：Windows 经常驻的 PowerShell 探测进程调用 winspool（`OpenPrinter`、`StartDocPrinter` 数据类型 `RAW`、`WritePrinter`），不新增原生模块；macOS 用 `lp -o raw`。只发到系统打印机列表里存在的打印机（安全底线不变）。
- **能设的**：浓度、速度、纸张（宽、高、间隙 / 黑标）、打印方向、撕纸 / 剥离模式；动作：纸张校准（自动测间隙）、走一张纸、打印机自检页、恢复出厂设置（二次确认）。
- **设置怎么生效**：保存时发一次；之后每次打印前不重复发（指令设置会写进打印机）。指令是单向的，打印机状态仍来自驱动（读打印机自身状态要直连 USB，不在这一期）。
- 指令生成是纯函数（每种指令集一个文件），用单元测试对照指令手册的示例。

### 7.2 一键诊断修复

「打印机」页每台一个「诊断」，逐项检查并给出结果和修复按钮：

| 检查 | 修复 |
|---|---|
| 系统里有这台打印机、驱动报告的状态 | 打开驱动设置 / 重新安装驱动（7.3） |
| USB 设备在位（Windows：`Get-PnpDevice`；macOS：`system_profiler`） | 提示换线、换 USB 口 |
| 后台打印服务在运行 | 重启服务（Windows 弹一次管理员权限；macOS `cupsenable`） |
| 队列里有卡住的任务 | 清除本程序的任务；清除全部（管理员权限） |
| 驱动纸张和它负责的纸一致 | 自动设置驱动纸张（路线图里已有的那项，管理员权限，失败回滚） |
| 指令集能通信（发一条无害的查询或走纸） | 改指令集 |
| — | 纸张校准、打测试页 |

检查项是纯逻辑（输入系统命令的输出，给出结论），每个平台分别测。

### 7.3 驱动安装

- **在线清单**（不进仓库，地址是设置项，官方安装包构建时注入，和中转地址一样）：USB VID / PID → 品牌、型号、指令集、Windows 官方驱动下载地址、文件大小、SHA-256、静默安装参数、要求的签名者；macOS 的官方 pkg 地址或下载页。清单本身带签名，程序内置公钥核对，防止被篡改。
- **流程**（Windows）：发现没有驱动的 USB 打印设备（PnP 状态异常）→ 在清单里找到型号 → 下载官方安装包 → 核对大小、SHA-256、Authenticode 签名者 → 弹一次管理员权限静默安装 → 重新列打印机，自动按纸张建议分配。
- **macOS**：清单里有官方 pkg 就下载核对后用系统安装器（输管理员密码）；没有就打开官方下载页。
- 清单里没有的型号：给出「用系统自带的通用驱动」或「到厂家官网下载」的指引。

## 8. 子项目 6：共享与远程打印

### 8.1 局域网共享（IPP）

- **打印机端**：设置里开「局域网共享」后，本机起一个 IPP/2.0 服务（端口默认 8631，631 在 macOS 上被 CUPS 占着；被占用时自动换，和本机接口一样）。每种已分配打印机的纸张是一台共享打印机：`/printers/<纸张名>`（例如「60×40 标签」「100×180 面单」），用 `bonjour-service` 广播 `_ipp._tcp`。
- **支持的操作**：`Get-Printer-Attributes`、`Validate-Job`、`Print-Job`、`Get-Jobs`、`Get-Job-Attributes`、`Cancel-Job`；文档格式 `application/pdf`、`image/jpeg`、`image/png`。IPP 编解码自己写（二进制格式简单），用协议规范里的样例做单元测试。
- **收到的任务**：走子项目 4 的流程（整页 / 去白边，缩放到这张纸），按纸张找打印机，记录来源「局域网共享」并记下对方电脑的地址和用户名。
- **访问控制**：只对局域网开放（防火墙规则和本机接口一起加）；可选「共享密码」（IPP 基本认证）；新电脑第一次打印时界面顶部询问「允许 / 拒绝」（复用本机接口的网站询问条）。
- **对方怎么用**：Windows「添加打印机 → 按地址」，用系统自带的 IPP 驱动；macOS 在「打印机与扫描仪」里自动发现。

### 8.2 异地远程打印（经中转服务）

- **共享码**：这台电脑在「共享」页生成远程共享链接（私有，可设有效期、随时撤销），复用手机扫码的会话、端到端加密、背压和排队。
- **对方**：任何设备的浏览器打开链接（中转服务上的「远程打印」页，和扫码页同一套前端）：上传 PDF / 图片，或选一个共享出来的模板填字段；选纸张、份数；看到排队和打印结果。多人可以同时连，任务在这台电脑上按打印机排队。
- **大文件**：中转服务现在单帧上限按手机的标签图定；远程打印改为分块传输（每块 256KB，单个任务 ≤ 20MB），协议版本加 1，不兼容旧版本（旧客户端提示更新）。
- **记录**：来源「远程」，记下对方设备名；打印结果回给对方页面。

## 9. 出错和安全

- 所有新输入都不可信：模板、Excel、PDF、IPP 请求、远程任务、在线清单都经过校验，有大小和数量上限；PDF 只在 sandbox 的隐藏窗口里渲染。
- 管理员权限只在用户点了按钮时弹，每次说明要做什么。
- 下载的驱动必须核对 SHA-256 和签名者，任何一项不对就不装并说明。
- 失败给中文提示和下一步；错误连同上下文写日志，不吞异常。

## 11. 工程规范（用户 2026-10-01：参考谷歌代码规范和 Chrome 的做法）

### 11.1 代码风格：Google TypeScript Style Guide

项目原有的约定（中文注释、常量带单位、Biome）照旧；下面几条按谷歌规范统一，新代码必须遵守，改到的旧代码顺手改：

- **只用具名导出**，不用 `export default`；不用 `namespace`。
- **类型**：不用 `any`（外部输入用 `unknown` 再收窄）；对象形状用 `interface`，联合、映射才用 `type`；不用 `@ts-ignore`；非空断言 `!` 只在紧挨着的检查已经保证时用，并写一句为什么。
- **命名**：类、接口、类型 `UpperCamelCase`；函数、变量 `lowerCamelCase`；模块级常量 `CONSTANT_CASE`；缩写当单词写（`IppServer`、`parseXml`，不写 `IPPServer`）；文件名小写加连字符。
- **控制流**：`===`；`for...of` 代替 `forEach`（需要提前退出、`await` 时尤其如此）；不在条件里赋值。
- **导出的函数、类、接口写文档注释**：说做什么、参数和返回的含义、会抛什么错。
- **类**：成员默认 `private readonly`；依赖由构造参数传入（可测）；不用 `#private`。

### 11.2 工程做法：参考 Chromium

- **两条法则（Rule of 2）**：「不可信的输入」「不安全的实现」「高权限进程」三样最多占两样。落到这里：
  - Excel、PDF 都在**隔离的子进程**里解析：Excel 用 Electron 的 `utilityProcess`（不带 Node 集成以外的权限，超时、内存上限到了就杀掉）；PDF 在 sandbox 的隐藏窗口里渲染（和 Chrome 在渲染进程里跑 PDF 一样）。主进程只收结构化的结果，再校验一遍。
  - IPP 请求、远程任务、在线驱动清单在主进程里解析（TypeScript，内存安全），但每一层都有大小、数量、时间上限，解析失败一律拒绝。
- **IPC 当作信任边界**（Chrome 的 Mojo 做法）：渲染进程传来的每个参数都在主进程校验（现有的 `ipc-validators.ts`）；新通道只暴露最小能力（例如「打印这个批次」，不是「执行任意打印参数」）。
- **小步提交、每步可测**（Chromium 的小 CL）：一个提交只做一件事、单独能过 `bun run check`；每个子项目一个 PR，CI 在 Windows 和 macOS 上都过才合。
- **测试金字塔**（Chromium 的 unit / browser / pixel tests）：纯逻辑单元测试为主；E2E 只测主流程；视觉验收对应 pixel test，界面改动必须逐项截图核对。
- **快速失败**（`CHECK` 的思路）：不变量被破坏时立刻抛出带上下文的错误，不带着错误状态继续；面向用户的错误给中文说明和下一步。
- **最小权限**：管理员权限、网络监听、下载安装都由用户明确触发，默认关闭的能力（局域网共享、远程共享）要在设置里打开。
