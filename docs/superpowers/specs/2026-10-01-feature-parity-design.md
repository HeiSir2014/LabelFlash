## 2. 共同原则

- **所有入口走 `PrintService`**：批量、PDF、IPP、远程打印都是新的「来源」（`batch`、`pdf`、`ipp`、`remote`），照常决定打印机、排队、写打印记录、发打印结果通知；记录能搜、能重打。
- **只有黑白**：热敏标签机没有灰色。图片、PDF 都按打印机分辨率转成黑白（阈值或抖动），预览里看到的就是打出来的样子。
- **对齐打印点**：位置、线、条码模块、二维码模块都取整数个打印点（沿用面单的做法）。
- **新增依赖**（都只在主进程或构建时用，bundle 仍然自包含，由 `verify:bundle` 把关）：

  | 依赖 | 许可 | 用途 | 为什么不自己写 |
  |---|---|---|---|
  | `bwip-js` | MIT | 条码编码（只用 `raw()` 取条空宽度和二维码点阵，画法自己来） | 100 多种码制，EAN / UPC 校验、DataMatrix、PDF417 自己写既大又容易错 |
  | `read-excel-file` | MIT | 读 `.xlsx` | 只读、体积小；CSV 用现有解析器（含 GBK） |
  | `pdfjs-dist` | Apache-2.0 | 把 PDF 页渲染成位图 | PDF 渲染不可能自己写 |
  | ~~`bonjour-service`~~ | — | 不引入（实施时改） | 它把所有网卡（含虚拟机、WSL、VPN）的地址都广播出去、只从默认网卡发组播；自己写的应答器只回答自己的几条记录，按局域网网卡过滤，见第 8.1 节 |

  实施计划里用 context7 核对每个库的当前版本和 API；`.xls`（97-2003）不支持，提示另存为 `.xlsx` 或 CSV。

## 3. 子项目 1：标签设计器

### 3.1 模型

```
CanvasTemplate { kind: 'canvas', id, name, paper, printer, elements: CanvasElement[] }
```

- **每个元素**：`id`、`name`、`x`、`y`、`width`、`height`（mm），`rotation`（0 / 90 / 180 / 270），`locked`。数组顺序就是上下层，后面的在上面。
- **文字** `text`：内容（可含 `{字段名}`、`{序号}`、`{日期}`、`{时间}`），字号、加粗、水平 / 垂直对齐，放不下时：缩小（默认，最小原字号 60%）→ 折行 → 截断加「…」；反白。
- **条码** `barcode`：码制（下拉列常用的 10 种：Code128、EAN-13、EAN-8、UPC-A、UPC-E、Code39、Code93、ITF-14、库得巴、GS1-128；「更多」里是 bwip-js 支持的其余码制，含 DataMatrix、PDF417）；内容；号码印在下面（开 / 关、字号）。
- **二维码** `qr`：内容、容错（和现在的标签一致，`qrcode` 编码）。
- **图片** `image`：PNG / JPEG 原图（单张 ≤ 1MB，整个模板 ≤ 4MB），转黑白方式（阈值 + 阈值大小 / 抖动），等比放入框内。
- **线** `line`：横或竖，粗细，实线 / 虚线。
- **矩形** `rect`：边框粗细（0 = 无边框）、填黑、圆角。
- **表格** `table`：行高、列宽（mm）、边框粗细，每格文字（可含变量）、字号、加粗、对齐；不合并单元格。
- **限制**（`CANVAS_LIMITS`，每项写取值依据）：元素 ≤ 100、文字 ≤ 500 字、表格 ≤ 20 行 × 10 列、最小字号 1.5mm、线 ≥ 0.25mm。

### 3.2 分层

| 层 | 文件 | 作用 |
|---|---|---|
| core | `templates/canvas-model.ts`、`sanitize-canvas.ts`、`canvas-layout.ts`、`templates/mono-image.ts` | 模型和限制；校验（不合法回到默认值，超出纸张的元素收进纸内）；展开变量、排文字（复用 `fitParagraphs`）、取整到打印点；`mono-image.ts` 是灰度像素（编辑器在 1b 的 sandbox 页面里解码图片文件后存进模板）→ 黑白点的纯函数（缩放、阈值 / Floyd–Steinberg 抖动、编成 1 位 BMP），不碰图片文件本身，主进程和测试都能直接用 |
| main | `printing/canvas-html.ts`、`printing/barcode.ts` | 画 HTML（绝对定位，mm）；`barcode.ts` 统一出条码的画法和限制（bwip-js `raw()` → 按打印点画 SVG）；面单保留自己的 Code128 编码器，只共用这里的画法和限制，输出逐字不变（快照把关）；图片按 `mono-image.ts` 转黑白后编成 1 位 BMP 嵌进 HTML（不是 SVG 路径：抖动照片的黑白点交替密集，路径字符串能到几 MB，BMP 只随点数线性增长） |
| renderer | `components/canvas-editor/*`、`lib/canvas-edit.ts`（及 `canvas-snap`、`canvas-history`、`canvas-table`、`canvas-view`、`gray-image`） | 三栏编辑器；移动、缩放、对齐、等距、吸附、撤销重做、复制粘贴、表格行列、图片转灰度都是 `lib/` 里的纯函数，有单元测试；图片文件在页面里解码，模板里只存灰度像素 |

`renderLabelHtml` 按 `kind` 分派到 `canvas-html`；预览、打印、PDF 共用同一份 HTML。

### 3.3 编辑器（画布优先，2026-10-06 按平板上的绘图、排版软件改）

最初是经典三栏（工具条、左元素、中画布、右属性）。2026-10-06 一次实际操作的走查发现：画满纸的边框矩形吞掉画布上所有的点击和框选，条码不印时看不出是哪一个、要多宽，图层全叫「文字 / 文字 2」，没有右键菜单、就地改字和全选，退出时没保存的模板直接丢掉。用户要求「按最佳实践做到可用易用」「按面单和标签最佳实践，但不要太复杂」，并给出方向：尽量照参考产品（平板上易用的绘图、排版软件）来设计和优化——内容优先，周围安静，操作放在正在改的东西旁边，点击目标大，直接拖、捏、滚。实施计划见 `docs/superpowers/plans/2026-10-06-designer-usability.md`。

- **入口**：模板页「新建自由设计模板」（空白、60×40，进设计器后在检查器「模板」页改纸张），或复制内置的吊牌示例，或从模板库新建；自定义的自由设计模板点「编辑」进设计器。空画布中间写「从左边点一个元素加进来，或 从模板库新建」。
- **上**：一条窄栏：预览内容（默认最近一次扫码，可自填；配置中心里扫码也填进来）、网格、吸附、「?」（快捷键表）。
- **左**：竖排的元素图标（图标下两三个字），点一下放到画布中间（正好压在已有元素上时往右下错开 2mm），或拖到画布上松手的位置。新条码默认 `{编码}`、50mm 宽。
- **中**：画布要安静，突出的是标签：纸色底、淡墨刻度的毫米标尺（指针位置一条细线、选中的范围标出来；不用模板页预览那条黄色软尺），1mm 网格默认关（窄栏打开，很淡），安全边距是很淡的虚线（纸边往里 1.5mm）。画布是**真实打印 HTML**（和模板页预览同一条路，草稿变了 150 毫秒后重新排版），上面一层透明覆盖层画选框、控制点、参考线和框选；元素框平时不画，指针移到元素上才显示它的框，不印的、条码快不够宽的一直显示；拖动时只动覆盖层，松手才改模板、重新排版。所见即所打。这一张不印的元素浅红底、框里写短原因（「条码不印：框不够宽」），条码宽度离最小不到 10% 时黄框。左上角撤销、重做；右下角缩放胶囊（− 百分比 +，点百分比选适合窗口 / 100% / 200%）。
- **浮动工具条**：选中时在选框上方（放不下在下方，不盖控制点、旋转手柄和撤销按钮），一行不折、六到八个按钮，真的拖起来时才藏（按下没挪不藏，不闪）。文字：字号 −/+（数字带 mm）、加粗、一个对齐按钮（点一下换下一种）、改字；条码、二维码：绑定字段（选项写这段预览内容里的值）、需要时「放大到能印」；多选：六个对齐；都有复制一份、删除和「⋯」。锁定、叠放、等距收在「⋯」打开的完整菜单里。点了工具条、检查器的按钮之后焦点留在画布上，接着能按 Ctrl+Z、方向键。旋转手柄平时淡淡的，指针移到选中的元素上才完全显出来。
- **右（检查器）**：分段标签。选中一个：本类设置（「文字」「条码」……：名称、内容、插入字段、字号……）、「排列」（X/Y、宽/高、旋转、锁定、对齐到安全区、叠放）、「图层」；没选中：「模板」（名称、纸张「60×40 标签 · 样衣标签」、打印机）、「图层」；多选：「排列」（对齐、等距、叠放）、「图层」。选中元素的问题写在最上面，条码放不下时有「放大到能印」（按排版算出的最小尺寸再留 10%，纸放不下就到最小尺寸，再放不下说明要换短一点的内容或码制）。图层：上层在前，没改过名的写内容摘要（「品名：{编码}」「条码 {编码}」「表格 3×2」），每行隐藏（只在设计器里隐藏，照常打印）和锁定，双击改名，拖动排序。
- **底部**：打印前检查（见 3.4）收成一条：没问题时一句话，有问题时「⚠ N 项」加最要紧的一条（不印的在前），点开是清单，点一项选中那个元素；操作条「放弃修改」「打印一张试试」「保存模板」。「打印一张试试」按预览内容打印没保存的草稿，和预览一样识别、加工，不写打印记录、不占防重复窗口。
- **输入设备**：支持鼠标、键盘、触控板和数位板；不支持触摸屏。
- **鼠标和数位板**：点中按位置算，只有边框的矩形、线只在描边 ±4 屏幕像素内点中，框里面落到下面的元素上；锁定的点不中、框不中，只能在图层里选。点选、Shift+点击或 Ctrl+点击（macOS 上 ⌘+点击）加选减选、Alt+点击轮流选叠在下面的元素；在空白处或按住 Ctrl 拖过 3px 框选（碰到就算，只有边框的矩形要框到边框）；按住选中的元素拖动整组，多选时合起来的外框里任何地方都能拖。控制点看到 10px、可点 24px；下方的旋转手柄只转直角；缩放时 Shift 保持比例，图片和二维码默认保持（Shift 放开）。拖动时吸附到纸边、安全边距、纸的中线、其他元素的边和中线（网格只显示，不吸），写出和邻居的间距（两边相等标「=」），指针旁显示位置、尺寸或角度。双击文字（或表格的一格）就地改字：Enter 换行，Ctrl+Enter 或点外面改完，Esc 放弃，整段是一步撤销。右键（数位板笔杆按键、长按）打开页面里的菜单：复制、粘贴、复制一份、删除、四个叠放、锁定 / 解锁，多选时有「对齐」「等距」子菜单（等距三个以上才能用）；画布上不弹系统菜单。中键或空格 + 拖动平移，两指滑动滚动，Ctrl+滚轮、触控板捏合以指针为中心缩放。数位板的笔和鼠标走同一条路（按下后挪不到 3px 不算拖动，笔尖抖动不会挪动元素）；不支持触摸屏。
- **键盘**：方向键 0.1mm、Shift+方向键 1mm（按住算一步撤销）；Delete / Backspace 删除；Esc 取消选中（没选中时照常返回列表）；Ctrl+A 全选（锁定的除外）；Ctrl+C / V（设计器自己的剪贴板：页面没有系统剪贴板权限）、Ctrl+D 复制一份；Ctrl+] / [ 上下移一层、加 Shift 置顶置底；Ctrl+Z / Y（最多 100 步，同一个输入框连续输入、连续按方向键各算一步）；Ctrl+0 适合窗口、Ctrl+1 100%；菜单键或 Shift+F10 打开菜单；F1 快捷键表。macOS 上 Ctrl 换成 ⌘，提示里按平台写。
- **扫码不受影响**：画布是可聚焦的区域，不是输入框；它只处理方向键、Delete、Esc、F1、菜单键、空格和 Ctrl 组合键，字母数字照常被当作扫码送进「预览内容」。
- **退出时没保存的模板**：托盘「退出」、系统退出时，模板页还有没保存的修改就问「保存并退出 / 不保存退出 / 取消」（在批量打印的确认之前问）；保存走界面平常的保存流程，没存上不退出并说明；系统关机、注销时不问。就地改字时窗口失去焦点（点托盘、切到别的程序）算改完，改的字先进草稿再问。「重启更新」在装之前就问（安装程序一拉起来就会结束本程序，退出时再问来不及），选「取消」不装；有没保存的模板时不静默更新。界面进程崩了，没保存的修改随它没了，不再拿它挡退出。

### 3.4 替用户守住的底线（打印前检查，列在底部，不挡保存）

1. 元素超出安全边距：「靠近纸边，可能打不全」。
2. 条码：模块对齐打印点、两侧留 10 个模块空白；放不下、内容不合码制（例如 EAN-13 位数不对、校验位错、有中文）就不印，并说明原因。
3. 二维码放不下：降容错，仍不行就不印并说明。
4. 字段这一张没有：这一项不印（和面单一样）。
5. 文字缩到最小仍放不下：截断并提示。
6. 图片太大：选图时按像素上限（单张 1MB 灰度像素、边长 4000）缩小后存；文件超过 20MB 不读；整个模板的图片超过 4MB 不插入，并说明上限。

### 3.5 和现有功能的关系

自由设计模板和标签、面单模板一样：能设为当前模板、被规则绑定、被按字段换模板选中、有自己的纸张和打印机；本机接口 `GET /v1/templates` 列出它用到的变量；批量打印直接用。内置的吊牌示例（`builtin:canvas-tag`）留在模板列表里，可以直接用；按行业分类的模板在模板库（子项目 2），复制后使用。

## 4. 子项目 2：模板库

- **内容**：约 20 个内置自由设计模板，分 7 类：服装吊牌（3）、价签（3）、商品条码（EAN-13 / Code128，3）、鞋盒标（2）、食品标签（品名、配料、生产日期、保质期，2）、珠宝 / 小商品尾巴标（2）、仓储（货架 / 库位、资产标签、箱标，各 1）。纸张覆盖 30×20、40×30、50×30、60×40、70×50、100×100、100×150。
- **界面**：配置中心「模板」页加「从模板库新建」：左边分类，右边缩略图（就是真实排版的预览），按纸张筛选；点「用这个模板」复制成自定义模板并进入设计器。
- **字段名约定**：模板库统一用「品名、编码、颜色、尺码、价格、商品码、生产日期、保质期、货架号」等中文字段名，和内置识别规则、批量打印的列名自动对应。
- **测试**：每个模板的快照、视觉验收逐个截图、E2E 抽一个从模板库新建并打印。
- **实现时定下的细节**（2026-10-02）：
  - 18 个模板（各类个数照上面）；纸张高度下限从 25mm 降到 20mm，加预设「30×20 标签」。哑铃形尾巴标（72×10 这类）比下限还矮，这一期不做，珠宝 / 小商品用 30×20、40×30 的矩形标签。
  - 模板库的模板编号是 `library:xxx`，不进模板列表：不能设为当前模板、不能被规则绑定、本机接口不列出，要用先复制。「样衣吊牌」复用内置吊牌示例的元素。
  - 缩略图：主进程按每个模板的示例数据现排（和打印同一份 HTML，203dpi），一次 IPC 拿全部，界面用 `sandbox=""` 的 iframe 缩小显示，不超过实物大小。
  - 「用这个模板」复制成自定义模板（名字不加「副本」）并进设计器；设计器先按这个模板的示例数据预览，「打印一张试试」打的也是示例数据；打字或扫码改了预览内容就回到按内容识别。页面只交模板库编号，示例数据由主进程取。
  - 字段名统一在 `LIBRARY_FIELD_NAMES`（29 个），测试核对和内置规则、批量打印一致：用这些名字做 Excel 表头，批量打印能把每个模板的变量全部自动对上。内置规则「多行键值」把「编码」当「款号」的别名，这一条没改。
  - 版式：边距 ≥2mm，除了「样衣吊牌」——它复用内置吊牌示例（`builtin:canvas-tag`）的元素不重写，那套元素的下边距是 1.8mm（内置模板本身的坐标，改它会牵动设计器、视觉验收等多处，不在这次改动范围）；零售商品条码用 EAN-13，货号、库位、箱号用 Code128，资产编号用二维码；每个模板在 203、300dpi 下排版、编码都没有问题（单元测试 + HTML 快照），系统字体下没有被裁的行（E2E，Windows 和 macOS）。

## 5. 子项目 3：批量打印

- **入口**：工作台标题栏加「批量打印」，打开全窗口的批量打印页（和配置中心同级）；配置中心里不打印的规则不变。
- **步骤**（一页里自上而下，不是多步向导）：
  1. **选模板**（任意一类）。
  2. **数据**：导入 `.xlsx` / `.csv`（拖进窗口也行），或者在表格里直接粘贴（从 Excel 复制），或者不用数据、只按序号打 N 张。第一行是表头；最多 10,000 行。
  3. **对列**：模板用到的每个变量对一列（按列名自动对上，对不上的标红，可手动选或填固定值）。
  4. **序号** `{序号}`：前缀、起始、步长、位数（补零）、后缀；也可以对到数据里的一列。
  5. **份数**：每行固定几份，或对到数据里的「份数」列。
  6. **预览**：左边数据表（可勾选要打的行、搜索），右边当前行的真实预览，上一张 / 下一张；有问题的行（缺字段、条码不合法）标黄，汇总在顶部。
  7. **打印**：进度条（已发送 / 总数）、暂停、继续、取消；失败的行可以单独重打；不受防重复窗口影响。
- **实现**：主进程 `batch/`：读文件（`read-excel-file`、现有 CSV 解析）→ 行 → `PrintService.printFields`（来源 `batch`，带批次号）；每台打印机一个串行队列（现有），批量任务按行依次入队，进度经 IPC 推给界面。core 里放纯逻辑：列名匹配、序号生成、份数展开、行校验，各有单元测试。
- **记录**：每张一条打印记录，来源「批量」，带批次号和行号；打印记录里可以按批次筛选、整批重打失败的。
- **本机接口**：已有的批量提交不变。
- **实现时定下的细节**（2026-10-02）：
  - 行号从 1 数，不含表头；序号按「要打的行」的顺序数（第一行要打的是起始值，跳过的行不占号），同一行的几份序号相同。
  - `{序号}` 不是新的固定变量：批量打印把它作为名为「序号」的字段交给模板，三类模板都按字段展开。「显示全部字段」的标签模板没有写 `{序号}`，由操作员勾「印序号」决定（只按序号打时一定印）。
  - 「显示全部字段」的模板：表格的每一列都是一个字段（空格子不印）。
  - 份数列空着按 1 份；0 或不是 0–100 的整数时这一行不打并标黄。一批最多 2 万张。
  - 有问题的行照样打（缺的那一项空着），只是标黄提醒；要跳过就取消勾选。
  - 打印机不能用（没分配、找不到、缺纸离线）时整批自动暂停，那一张不算失败，继续时重打它；驱动报错、超时记为失败、接着打。
  - 重打失败的（单行或整批）用同一个批次号、行号、份号和当时的模板、字段；打印记录按「每行每份最新一条」判断还失败着的。
  - 表格只在主进程里留最近一张；批次结束（打完、取消）之后没解决的失败不再提醒，退出时也不再确认——那是操作员自己的决定。
  - 批次还在打或暂停中时退出程序：还没轮到的标签（不含正在打的那一张）弹确认，选「仍要退出」才记成打印记录（失败原因 `CANCELED`，表示从来没交给过打印机），之后可以找到并重打；系统关机、注销时不弹，直接放行。
  - Excel 在 `utilityProcess` 里读：一个文件一个子进程，30 秒超时、512MB 堆上限；文件 ≤ 20MB、≤ 1 万行、≤ 100 列、单元格 ≤ 1000 字、整表 ≤ 500 万字。

## 6. 子项目 4：PDF 打印

- **入口**：工作台「打印 PDF」（也可以把 PDF 拖进窗口）。
- **渲染**：主进程开隐藏窗口（sandbox，只加载本程序的页面）用 `pdfjs-dist` 把每页按目标打印机分辨率渲染成位图；最多 200 页、单个文件 ≤ 50MB。
- **裁切方式**（自动识别，可改）：
  1. **整页**：整页缩放到纸张（按纸张方向自动旋转）。
  2. **去白边**：找内容的外框，裁掉四周空白再缩放（跨境面单常见）。
  3. **一页多张**：按大片空白或分割线把一页切成几块（例如 A4 上 2×2 四张面单），每块一张标签。
  4. **手动框选**：在第一页上画一个或几个框，后面每页按同样的位置裁（固定格式的平台导出件）。
- **输出**：每块 → 黑白位图（阈值 / 抖动）→ 放进按纸张生成的标签 HTML → 照常打印。预览是全部块的缩略图网格，可以删掉不要的、调整顺序、设份数。
- **记录**：来源「PDF」，记文件名和页码 / 块号；重打从记录里找回同一块（打印时缓存的黑白位图保留 7 天）。
- **纯逻辑**（core / 主进程不依赖 Electron 的文件）：内容外框检测、空白分割、旋转判断、缩放计算，用合成的位图做单元测试。
- **实现说明**（实施计划 `docs/superpowers/plans/2026-10-02-pdf-printing.md`）：
  - 渲染页是一个隐藏窗口，用内存里的独立会话（不和主窗口共用存储），CSP `default-src 'none'`，会话层拦下 `app://bundle/` 以外的一切请求，pdf.js 的 worker、字符映射、标准字体、解码器都随安装包；只经两个函数的 preload 和主进程通信，主进程按自己算出的尺寸核对每张位图。
  - 第一页按 96dpi 渲染来识别裁切方式；出块时每页按目标打印机的分辨率渲染（一页最多 1600 万像素，特大的页降低分辨率）。
  - 一页多张：先按 4mm 以上的空白缝切（行 → 列 → 行三层）；整页没有缝时才用分割线，而且只认正好落在 2–4 等分位置上的细线（区分切线和面单里的表格线）；小于 20mm 的零碎丢掉；几块大小差不多（±20%）才自动识别为一页多张。
  - 一块包成只有一张图的临时自由设计模板打印（不新建模板种类），渲染复用 `canvas-html.ts` 的 1 位 BMP；打印记录的模板编号是 `builtin:pdf-piece`。
  - 份数是全部块统一的；每块每份一条打印记录。按顺序打印、暂停、打印机问题自动暂停复用批量打印的 `BatchRun`。
  - 一次最多 1000 张（超出的不处理并说明）；缩略图按整数倍缩小、一格有黑点就算黑。

## 7. 子项目 5：打印机管理

### 7.1 标签机指令

- 打印机页每台打印机加「指令集」：自动（默认，按在线识别表 + 驱动名猜）/ TSPL / ZPL / EPL / 不发指令。
- **下发**：Windows 经常驻的 PowerShell 探测进程调用 winspool（`OpenPrinter`、`StartDocPrinter` 数据类型 `RAW`、`WritePrinter`），不新增原生模块；macOS 用 `lp -o raw`。只发到系统打印机列表里存在的打印机（安全底线不变）。
- **能设的**：浓度、速度、纸张（宽、高、间隙 / 黑标）、打印方向、撕纸 / 剥离模式；动作：纸张校准（自动测间隙）、走一张纸、打印机自检页、恢复出厂设置（二次确认）。
- **设置怎么生效**：保存时发一次；之后每次打印前不重复发（指令设置会写进打印机）。指令是单向的，打印机状态仍来自驱动（读打印机自身状态要直连 USB，不在这一期）。
- 指令生成是纯函数（每种指令集一个文件），用单元测试对照指令手册的示例。
- **实现时定下的细节**（2026-10-02）：
  - 每一项都可以「不改」：只发操作员设了的项，不把没碰过的设置改成程序的默认值。设置存在设置表的 `printerCommands`（不加迁移），最多 32 台。
  - 「自动」：先查 5c 的在线驱动清单（`DriverHints.modelForDriverName`，按型号；清单没接入前是 `NO_DRIVER_HINTS`，什么都查不到），再看驱动名里是否单独写着 TSPL、ZPL 或 EPL（写着两种的不猜）；都认不出就不发，请操作员选。
  - 各指令集的范围：TSPL 浓度 0–15、速度 2–5 英寸/秒；ZPL 浓度 0–30（`~SD`，绝对值）、速度 2–6；EPL 浓度 0–15、速度 1–4 档。间隙 / 黑标 2–10mm。ZPL、EPL 按打印点下发，分辨率默认按驱动报告的（读不到按 203dpi），可以手动选 203 / 300 / 600。
  - EPL 不设出纸方式：它的 `O` 命令同时管切刀和热敏 / 热转印模式。ZPL 恢复出厂只发 `^JUF` + `^JUS`，不发 `^JUN`（会清掉网络设置）。
  - Windows 的发送在常驻 PowerShell 探测进程里：第一次用时 `Add-Type` 编译一小段 C#，P/Invoke winspool（数据类型 RAW），字节 base64 走行协议，单次 ≤ 4KB；错误码 1801 / 5 / 1804 分别提示找不到、没权限、驱动不收 RAW。macOS 用 `lp -d <队列> -o raw`，字节走标准输入。其他平台「不支持」。
  - 指令不是标签：不经 `PrintService`、不写打印记录，每次发送写日志。动作按已保存的设置发送，表单有没保存的修改时动作按钮灰掉。

### 7.2 一键诊断修复

「打印机」页每台一个「诊断」，逐项检查并给出结果和修复按钮：

| 检查 | 修复 |
|---|---|
| 系统里有这台打印机、驱动报告的状态 | 打开驱动设置 / 重新安装驱动（7.3） |
| USB 设备在位（Windows：`Get-PnpDevice`；macOS：`system_profiler`） | 提示换线、换 USB 口 |
| 后台打印服务在运行 | 重启服务（Windows 弹一次管理员权限；macOS `cupsenable`） |
| 队列里有卡住的任务 | 清除本程序的任务；清除全部（管理员权限） |
| 驱动纸张和它负责的纸一致 | 自动设置驱动纸张（路线图里已有的那项，管理员权限，失败回滚） |
| 指令集能通信（发一条无害的查询或走纸） | 改指令集 |
| — | 纸张校准、打测试页 |

检查项是纯逻辑（输入系统命令的输出，给出结论），每个平台分别测。

- **实现时定下的细节**（2026-10-02）：
  - 检查顺序把「后台打印服务」放第一：它停了，系统列不出打印机、读不到队列，后面几项的「查不到」才说得清原因。系统一台打印机都列不出来时，打印机页只给「检查后台打印服务」。
  - 结论只说程序确知的事：驱动没报问题写「驱动没有报告问题」；取消任务写「已请求取消」，是否清掉由随后的重新检查说。
  - 「本程序的任务」：提交人是当前用户，且提交时间落在本程序某次把任务交给驱动（或 5a 的 RAW 下发）的时间段里（前后各 2 秒）；账本只在内存里，最多 500 条、保留一天。任务超过 1 分钟没打完、或驱动报错 / 暂停 / 缺纸，算卡住。
  - 管理员权限：Windows 上重启服务、清除全部任务、设置驱动纸张一定要；macOS 上重启打印系统、清除全部任务一定要，恢复打印机、设置纸张先以当前用户做，CUPS 拒绝时按钮换成「…（需要管理员权限）」。Windows 沿用防火墙的提权方式（提权脚本只信 `$PSHOME` 的模块、只用 .NET 系统程序集和系统目录的 `sc.exe`）；macOS 用 `osascript` 的 `do shell script … with administrator privileges`（命令和提示经 argv 传入、每个参数单引号转义），因为没有开发者签名用不了特权助手。
  - 自动设置驱动纸张：先不提权读驱动支持的纸张，挑不出来（没有这种纸、也不能自定义）就不弹确认、直接说明。Windows 把 PrintTicket 增量合进默认设置和当前账户的设置，驱动校验后的尺寸不对就不改，写进去回读不对就恢复；macOS `lpadmin -o media-default=`，回读不对就设回原来的。
  - 指令集一项是半手动的：指令单向，程序点「走一张纸」后问操作员「走出一张空白标签了吗」，没反应就打开指令集下拉。
  - 「重新安装驱动」等 7.3（5c）合并后才出现。

### 7.3 驱动安装

- **在线清单**（不进仓库，地址是设置项，官方安装包构建时注入，和中转地址一样）：USB VID / PID → 品牌、型号、指令集、Windows 官方驱动下载地址、文件大小、SHA-256、静默安装参数、要求的签名者；macOS 的官方 pkg 地址或下载页。清单本身带签名，程序内置公钥核对，防止被篡改。
- **流程**（Windows）：发现没有驱动的 USB 打印设备（PnP 状态异常）→ 在清单里找到型号 → 下载官方安装包 → 核对大小、SHA-256、Authenticode 签名者 → 弹一次管理员权限静默安装 → 重新列打印机，自动按纸张建议分配。
- **macOS**：清单里有官方 pkg 就下载核对后用系统安装器（输管理员密码）；没有就打开官方下载页。
- 清单里没有的型号：给出「用系统自带的通用驱动」或「到厂家官网下载」的指引。
- **实现时定下的细节**（2026-10-02，见 `docs/superpowers/plans/2026-10-02-driver-install.md`）：
  - 清单是一个签名信封文件（`format`、`keyId`、`payload` = 清单原文 base64、`signature` = Ed25519），签名覆盖固定的用途前缀加原文；公钥内置（可多把），私钥离线。
  - 版本号 = 签名时刻的 Unix 秒数，程序记住用过的最高版本（settings 表的独立键，界面改不到）；默认有效期 180 天，最长 400 天。连不上时用同一地址上次的清单（重新核对）。
  - 单个型号不合格时跳过；`schema` 比程序新时整份不用并提示更新。签名脚本对任何不合格都拒签。
  - Windows 检测：`Win32_PnPEntity` 里有问题代码的 `USB\VID_*` / `USBPRINT\*`，后者经父设备取 VID/PID；列出打印机类的设备和清单里有的设备。
  - Windows 安装：普通权限核对大小、SHA-256、Authenticode（Valid + Subject 逐字相同）→ 一次 UAC → 提权脚本复制到只有 Administrators / SYSTEM 能写的新目录、复核 SHA-256 后运行（exe 带静默参数、msi 用 msiexec /qn /norestart）→ `pnputil /scan-devices` → 每 2 秒列一次打印机、最多 30 秒找新打印机。超时 15 分钟。
  - macOS：USB 设备来自 system_profiler，按序列号 / 型号名和 CUPS 的 usb 队列对，只列清单里有、没有队列的；pkg 用 `osascript … with administrator privileges` 运行固定脚本（root 专属目录里复核 SHA-256 再 `installer`）。
  - 装完只提示给新打印机分配纸张，不自动分配（沿用打印机页「只建议」的规则）。
  - 清单放在中转服务那台服务器的 nginx 静态文件里，不经中转服务。

## 8. 子项目 6：共享与远程打印

### 8.1 局域网共享（IPP）

- **打印机端**：设置里开「局域网共享」后，本机起一个 IPP/2.0 服务（端口默认 8631，631 在 macOS 上被 CUPS 占着；被占用时自动换，和本机接口一样）。每种已分配打印机的纸张是一台共享打印机：`/printers/<纸张名>`（例如「60×40 标签」「100×180 面单」），用 `bonjour-service` 广播 `_ipp._tcp`。
- **支持的操作**：`Get-Printer-Attributes`、`Validate-Job`、`Print-Job`、`Get-Jobs`、`Get-Job-Attributes`、`Cancel-Job`；文档格式 `application/pdf`、`image/jpeg`、`image/png`。IPP 编解码自己写（二进制格式简单），用协议规范里的样例做单元测试。
- **收到的任务**：走子项目 4 的流程（整页 / 去白边，缩放到这张纸），按纸张找打印机，记录来源「局域网共享」并记下对方电脑的地址和用户名。
- **访问控制**：只对局域网开放（防火墙规则和本机接口一起加）；可选「共享密码」（IPP 基本认证）；新电脑第一次打印时界面顶部询问「允许 / 拒绝」（复用本机接口的网站询问条）。
- **对方怎么用**：Windows「添加打印机 → 按地址」，用系统自带的 IPP 驱动；macOS 在「打印机与扫描仪」里自动发现。
- **实现说明**（实施计划 `docs/superpowers/plans/2026-10-02-ipp-sharing.md`，用法和真机验证清单 `docs/lan-sharing.md`）：
  - IPP 编解码、属性集、任务表、六个操作、PWG / Apple 光栅解码、DNS 报文和 mDNS 应答都在 `src/core/ipp/`、`src/core/mdns/`（纯 TS，用 RFC 8010 附录 A 的报文测）；主进程 `src/main/ipp/` 只接线。
  - 免驱：Windows 的 IPP 类驱动按 IPP Everywhere 认、主要发 PWG Raster；macOS / iOS 系统自带的打印要 `_universal` 子类型和 URF。所以文档格式除了 PDF、JPEG、PNG，还收 `image/pwg-raster` 和 `image/urf`；格式按文件头认。JPEG / PNG 在 PDF 打印的 sandbox 渲染页里解码（IPP 有自己的一个渲染窗口），光栅在主进程里用内存安全的 TS 解。
  - 网址 `/printers/<纸张键>`（不用中文名：纸张键本来就 URL 安全、稳定、唯一）；实例名「60×40 标签 @ 电脑名」；mDNS 主机名 `labelflash-<实例编号前 8 位>.local`。
  - mDNS 不引入库：自己写的应答器只回答本程序的记录（服务类型、两个子类型、实例的 SRV / TXT、自己主机名的 A），只理局域网地址来的包，用对方所在子网那块网卡的地址回答；网卡按本机接口的规则去掉 Hyper-V、WSL、VMware、VPN 等虚拟网卡。
  - 只监听 IPv4（0.0.0.0，不逐块网卡绑：换 Wi-Fi、DHCP 换地址时不用重绑），连接一建立就按地址过滤：只接受和选中的某块局域网网卡同一子网的（本机回环只在开发 / E2E 的开关打开时）；先认证再读正文，没认证最多收 64KB；文档上限和 PDF 打印一样 50MB，所有连接同时在收的正文总量不超过两个最大请求；每个地址限速，密码错 5 次后每错一次锁 10 秒（锁着时不再算摘要）；每台电脑只看得到、只能取消自己的任务（按地址分：同一个 NAT 后面的几台电脑地址相同，互相看得到）。设了密码时，除了查打印机本身，打印、核对、取消、查任务都要密码。
  - 共享密码只存 scrypt 摘要（不需要取回原文），不放进「密钥」表（那张表能被 HTTP 查询步骤引用）。
  - 新电脑第一次打印：任务先收下、停在 pending-held，顶部询问，允许后处理，拒绝或 2 分钟没人点就中止；等确认时不占处理队列。决定按地址记住。
  - 页面和纸差不多大（±3mm）整页打，否则去白边；多份按整份依次打；每张一条记录（来源 ipp，带 PDF 的位图编号和电脑、用户），重打仍记原来的电脑。
  - 退出、更新：还有共享的任务时退出前问（在模板之后、批量和 PDF 之前，选「仍要退出」后最后才停共享），「重启更新」拒绝，静默更新等着。
  - 防火墙：原来那条按程序放行 TCP 的规则覆盖 IPP 端口（不限网段：本机接口的调用方可能在别的网段，共享在程序里按网段过滤）；UDP 5353 一条只在打开共享后由共享页的按钮加，只放行 LocalSubnet，安装包不加；查询分开，只有旧规则的电脑上本机接口不受影响。

### 8.2 异地远程打印（经中转服务）

- **共享码**：这台电脑在「共享」页生成远程共享链接（私有，可设有效期、随时撤销），复用手机扫码的会话、端到端加密、背压和排队。
- **对方**：任何设备的浏览器打开链接（中转服务上的「远程打印」页，和扫码页同一套前端）：上传 PDF / 图片，或选一个共享出来的模板填字段；选纸张、份数；看到排队和打印结果。多人可以同时连，任务在这台电脑上按打印机排队。
- **大文件**：中转服务现在单帧上限按手机的标签图定；远程打印改为分块传输（每块 256KB，单个任务 ≤ 20MB），协议版本加 1，不兼容旧版本（旧客户端提示更新）。
- **记录**：来源「远程」，记下对方设备名；打印结果回给对方页面。

## 9. 出错和安全

- 所有新输入都不可信：模板、Excel、PDF、IPP 请求、远程任务、在线清单都经过校验，有大小和数量上限；PDF 只在 sandbox 的隐藏窗口里渲染。
- 管理员权限只在用户点了按钮时弹，每次说明要做什么。
- 下载的驱动必须核对 SHA-256 和签名者，任何一项不对就不装并说明。
- 失败给中文提示和下一步；错误连同上下文写日志，不吞异常。

## 11. 工程规范（用户 2026-10-01：参考谷歌代码规范和 Chrome 的做法）

### 11.1 代码风格：Google TypeScript Style Guide

项目原有的约定（中文注释、常量带单位、Biome）照旧；下面几条按谷歌规范统一，新代码必须遵守，改到的旧代码顺手改：

- **只用具名导出**，不用 `export default`；不用 `namespace`。
- **类型**：不用 `any`（外部输入用 `unknown` 再收窄）；对象形状用 `interface`，联合、映射才用 `type`；不用 `@ts-ignore`；非空断言 `!` 只在紧挨着的检查已经保证时用，并写一句为什么。
- **命名**：类、接口、类型 `UpperCamelCase`；函数、变量 `lowerCamelCase`；模块级常量 `CONSTANT_CASE`；缩写当单词写（`IppServer`、`parseXml`，不写 `IPPServer`）；文件名小写加连字符。
- **控制流**：`===`；`for...of` 代替 `forEach`（需要提前退出、`await` 时尤其如此）；不在条件里赋值。
- **导出的函数、类、接口写文档注释**：说做什么、参数和返回的含义、会抛什么错。
- **类**：成员默认 `private readonly`；依赖由构造参数传入（可测）；不用 `#private`。

### 11.2 工程做法：参考 Chromium

- **两条法则（Rule of 2）**：「不可信的输入」「不安全的实现」「高权限进程」三样最多占两样。落到这里：
  - Excel、PDF 都在**隔离的子进程**里解析：Excel 用 Electron 的 `utilityProcess`（不带 Node 集成以外的权限，超时、内存上限到了就杀掉）；PDF 在 sandbox 的隐藏窗口里渲染（和 Chrome 在渲染进程里跑 PDF 一样）。主进程只收结构化的结果，再校验一遍。
  - IPP 请求、远程任务、在线驱动清单在主进程里解析（TypeScript，内存安全），但每一层都有大小、数量、时间上限，解析失败一律拒绝。
- **IPC 当作信任边界**（Chrome 的 Mojo 做法）：渲染进程传来的每个参数都在主进程校验（现有的 `ipc-validators.ts`）；新通道只暴露最小能力（例如「打印这个批次」，不是「执行任意打印参数」）。
- **小步提交、每步可测**（Chromium 的小 CL）：一个提交只做一件事、单独能过 `bun run check`；每个子项目一个 PR，CI 在 Windows 和 macOS 上都过才合。
- **测试金字塔**（Chromium 的 unit / browser / pixel tests）：纯逻辑单元测试为主；E2E 只测主流程；视觉验收对应 pixel test，界面改动必须逐项截图核对。
- **快速失败**（`CHECK` 的思路）：不变量被破坏时立刻抛出带上下文的错误，不带着错误状态继续；面向用户的错误给中文说明和下一步。
- **最小权限**：管理员权限、网络监听、下载安装都由用户明确触发，默认关闭的能力（局域网共享、远程共享）要在设置里打开。
