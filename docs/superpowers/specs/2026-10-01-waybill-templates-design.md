# 快递面单模板（格子版式）

- 日期：2026-10-01
- 状态：方案已确认（用户：「按最佳实践设计和开发」）；路线图第 3 个子项目「元素式模板和快递面单」的第一步
- 相关：`2026-09-29-multi-printer-paper-design.md`（纸张预设、按纸张分配打印机）、`2026-09-30-local-api-design.md`（第三方经本机接口带字段打印）

## 1. 目标与边界

第三方的订单系统已经取好运单号（直接和快递公司签约、或经第三方面单服务取号），经本机接口把运单号、分拣码、收寄件信息等字段交给我们，我们按面单版式排版并静默打印到装着面单纸的热敏标签机。

- **做**：格子版式的面单模板（按毫米分行分格，放文字、Code128 条码、二维码）；五套内置面单；复制后可改；本机接口和工作台照常使用（选模板、带字段、按纸张分配打印机、打印记录、重打）。
- **不做**：电商平台电子面单取的号（平台返回加密的打印数据，规定只能用平台自己的打印组件渲染打印）；对接快递公司接口取号；打印快递公司的商标（标识区只印公司名文字）；图片、旋转文字、自由拖放（以后需要再加）。
- **用词**：代码、文档里不写参考产品的名称，内置模板叫「平台标准一联 / 二联」。

## 2. 版式依据

2026-10-01 下载了电商平台公开的标准电子面单模板（各家的一联、二联共 13 份，模板里写有每个区域、每条线的毫米坐标），逐份画出来核对：

- **二联 100×180**：中通、圆通、申通、韵达、极兔几乎是同一套：0–15 标识与服务，15–30 大号三段码（右侧格口码），30–40 集包地，40–55 收件人，55–67 寄件人，67–89 运单条码（约 88×20），89–108 打印时间 / 条款与签收 / 二维码；切点后 110–120 存根条码、120–130 收寄件简写；130 以下是商家自定义区（100×40）。各家差别很小：有的没有集包地一行、有的这一行是分拨区代码。
- **一联 76×130**：各家模板的版面是 74–77 × 126–129，左右各留约 5mm；0–12 标识与打印时间，12–21 三段码，21–79 左边依次是运单条码、格口码与集包地、收件人、寄件人，右边一列是竖排的运单条码；79 以下是商家自定义区（70×30）。
- **顺丰、德邦**：平台上也是 100×180。顺丰：条码在左上、右侧时效与代收货款，往下目的地代码、收、寄、付款方式与声明价值、托寄物与签名、存根；德邦：条码上方是 4×2 的路由格（4 个站点名 + 4 个编码），下部末端路由码。
- **顺丰 100×150**：平台模板列表里有顺丰的 100×150（另有 76×130、100×210）。从上往下：标识与时效、运单条码（约 89×13）、目的地代码、城市代码 / 出港码 / 产品名、收件人（右侧 24×24 二维码）、寄件人、进港码与托寄物，98 以下是大块的备注区；分隔线都是虚线。
- 德邦自己的 100×177 在平台模板列表里没有（平台上德邦只有 100×180 和 76×130）：用户复制内置模板后改纸张和行高即可（第 5 节）。

内置模板照这些坐标的分区和比例来排（取整到 0.5mm 左右），不照搬对方的模板文件。

## 3. 模板模型

模板分两类，用 `kind` 区分（数据库里旧模板没有 `kind`，读出时当作 `label`）：

```ts
type LabelTemplate = QrLabelTemplate | WaybillTemplate;   // 共同部分：id、name、paper、printer
interface QrLabelTemplate { kind: 'label'; …现有字段… }    // 现在的「通用 / 样衣」版式，不变
interface WaybillTemplate {
  kind: 'waybill';
  marginsMm: { top; right; bottom; left };   // 版面四边留白
  lineWidthMm: number;                      // 分隔线粗细
  root: WaybillNode;                        // 版面按「行」分割的根
}
```

**版式是一棵分割树**，不是一堆浮动的框：

```ts
interface WaybillNode {
  sizeMm: number;                 // 在父分割里占多少：父按行分时是高度，按列分时是宽度
  ruleAfter: 'solid' | 'dashed' | 'none';   // 和下一个兄弟之间画什么线
  body: { split: 'rows' | 'columns'; children: WaybillNode[] }   // 再分
      | { content: WaybillContent };                              // 叶子
}
type WaybillContent =
  | { kind: 'empty' }
  | { kind: 'text'; paragraphs: Paragraph[]; align: 'left'|'center'|'right'; valign: 'top'|'middle'; inverse: boolean }
  | { kind: 'barcode'; value: string; showText: boolean; textSizeMm: number; vertical: boolean }
  | { kind: 'qr'; value: string };
interface Paragraph { text: string; fontSizeMm: number; bold: boolean; wrap: boolean }
```

- **尺寸永远加得满**：每个分割的最后一个子项占「剩下的」，不存自己的尺寸（存了也按剩余重算）。所以每行的格宽加起来一定等于这一行的宽，行高加起来一定等于版面高，不会有缝或重叠。前面的子项加起来太大时按比例缩小，给最后一项留出最小尺寸。
- **线只画一次**：线画在兄弟之间（`ruleAfter`），相邻两格共用这一条；线的长度就是父格子的宽或高，所以「只在左半边画横线」用嵌套分割表达（例如一联单左列的横线不穿过右边的竖条码）。
- **文字里的变量**：`{字段名}`、`{日期}`、`{时间}` 等，和备注、二维码文本同一套（`note-text.ts`）。段落里有变量、而变量全都是空的，整段不印（例如没有「代收货款」时，「代收货款：{代收货款}」这一行不出现）；部分为空的照常印，空的位置印成空。
- **反白**（`inverse`）：黑底白字，用于「收」「寄」「集」和服务标签。只有展开后有字时才画黑底，四边缩进一点，上下相邻的两个黑块之间留白缝。
- **限制**：最多 80 个格子、嵌套 6 层；字号 1.5–14mm；段落最多 4 段、每段 200 字；线宽 0.2–1mm；留白 0–10mm。超出的输入在 `sanitize` 里收敛（第 1 层校验和现有模板一样：非法字段回到默认值）。

## 4. 排版与渲染

打印窗口不运行脚本（安全要求），所有位置和换行都在生成 HTML 之前算好，预览和打印共用同一份 HTML。

1. **几何**（`core/templates/waybill-layout.ts`，纯函数）：从根开始按尺寸切分，得到每个叶子和每条线的矩形。所有边界先换算成打印点（203dpi 一点 ≈ 0.125mm，驱动报告了分辨率时按驱动的）再取整：相邻格子的边界是同一个整数点，线宽是整数个点（至少 2 点），打出来粗细一致、不发虚。
2. **文字**（同一文件）：每格内边距左右 0.8mm、上下 0.5mm。字宽用 `text-fit.ts` 的字宽表（标签和面单共用）：2026-10-01 在 Edge 里逐个字符量了微软雅黑粗体（可打印 ASCII 每个字符和 ×、…、— 等符号），再放宽 3%；汉字和表里没有的字按一个字宽。原来的估算按类别取值、偏窄（把数字 1 当窄字），这次一并改掉，改完内置标签的输出一字未变。E2E 用系统字体真实渲染每套内置面单、逐行检查没有被裁掉，CI 在 Windows（雅黑）和 macOS（苹方）上都跑。逐字折行：西文和数字连成一段不拆开（太长才拆），句末标点不落在行首。放不下时按顺序：整格所有段落同比缩小字号（最小到原字号的 60%，且不小于 1.5mm）→ 还放不下，截到格子能容纳的行数，最后一行加「…」，并把这一格记为「放不下」。每一行在 HTML 里是单独一行（`white-space: pre`），浏览器不会再折行。
3. **条码**：Code128（`main/printing/code128.ts`，自己实现，按标准自动选 B / C 子集、算校验位，不引入依赖）。每个模块取整数个点（203dpi 上 2–4 点，其他分辨率按比例），两侧各留 10 个模块的空白，在格子里居中；`vertical` 时条码转 90°（一联单右侧的竖条码）。放不下最小模块宽时不印，记为「条码放不下」。号码印在条码下方居中（`showText`）。
4. **二维码**：沿用 `planQr`（容错 M，放不下逐级降低，仍放不下不印）。
5. **HTML**：版面是绝对定位的格子（`left/top/width/height` 用 mm），线是单独的细条；页面尺寸 = 模板纸张。

生成时发现的问题统一成 `RenderWarnings`（`src/shared/render-warnings.ts`：`qrOmitted`、`barcodeOmitted`、`overflowCells`），标签和面单共用；预览 `LabelPreview.warnings` 带回界面，贴在标签底边（和原来「二维码放不下」的提示同一处）。打印照常进行，只是少印那一部分。

## 5. 内置模板

| 平台标准二联 | 100×180（切点 110 / 70） | 中通、圆通、申通、韵达、极兔 |

## 6. 界面

- **模板页**：列表里面单模板和标签模板放在一起（内置 / 自定义两组不变），列表项写出纸张。选中面单模板时预览用「示例面单数据」（第 5 节的字段各一份示例值，主进程在 `label:preview-template` 里换上），不显示「预览内容」输入框，改为一句说明。
- **测试页**：测试内容填不出面单，规则绑的是面单模板时按通用标签打（纸张仍是这台打印机的）。
- **面单编辑器**（自定义的面单模板）：
  - 基本：名称、纸张、打印机（和标签模板一样）、四边留白、线宽；
  - 版式：左边是格子的大纲（按层级缩进，每项写「行 15mm · 3 格」「文字 {收件人} {收件电话}」「条码 {运单号}」），点一项在下面编辑它：尺寸（最后一项显示「自动：剩余 x mm」、不能改）、和下一格之间的线、内容（文字 / 条码 / 二维码 / 空白），以及「左右拆分」「上下拆分」「在后面加一格」「上移」「下移」「删除」；
  - 文字内容：对齐、垂直位置、反白、最多 4 段（每段：文字（可插入字段名）、字号、加粗、折行）。
- **工作台**：面单模板也能设为当前模板、能被规则绑定，扫码时按识别出的字段排版（字段名对得上才有内容）。主要入口是本机接口。

## 7. 本机接口

不需要新接口：`POST /v1/printJobs` 照常带 `template`（例如 `templates/builtin-waybill-platform-180`）和 `fields`。

- `GET /v1/templates` 的字段说明（`templateFields`）对面单模板列出所有格子里用到的变量，`mode` 为 `PICKED`。
- 接入说明 `docs/local-api.md` 加一节「打印快递面单」：内置模板名、字段名表、一个完整的请求示例。

## 8. 测试

- `waybill-layout`：分割树切分（尺寸加得满、最后一项吸收余量、取整到点后相邻边界相同）、线的位置、段落展开与丢弃、折行规则（西文不拆、标点不在行首）、缩小与截断。
- `sanitize-template`：旧模板没有 `kind` 读成标签模板；面单模板的各项夹到范围、超出层数和格数的截掉、最后一项尺寸重算。
- `code128`：已知内容的编码结果（含 B / C 子集切换和校验位）、模块数。
- `waybill-html`：五套内置模板配示例数据的快照；长地址缩小、截断后标记；条码放不下时标记。
- `template-fields`：面单模板列出全部变量。
- E2E：本机接口用内置面单模板打印（假打印机记下纸张 100×180）；模板页选中面单模板出预览；复制后编辑一格的文字，预览跟着变。
- 视觉：五套内置面单截图核对对齐（Windows 100% / 150%）；E2E 逐行检查没有字被裁掉（Windows、macOS）。
